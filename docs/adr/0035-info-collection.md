# 0035. 정보 수집: 해외 블로그 14곳·waedge 세 화면·네이버 투자자별 매매상위를 비주기로(본문까지, 서버에서만), 끊기면 텔레그램 + 화면 안내, 사람 확인은 체크박스만 한 번 누름(ADR 0026 결정 5 개정), 레이더의 끊긴 네이버 단계 교체, pykrx·LS 제거

- 상태: 채택 (2026-11-11, 사용자 요청과 질문 세 개의 답 — "체크박스 누르기만 허용", "새 출처 + 차단 통과 계층에 알림",
  "레이더의 끊긴 네이버 단계도 교체", 답에 덧붙인 지시 "수집기에 내 개인 IP를 쓰지 말 것, 서버 IP가 막히면 그 수집을 잠시 멈추고
  텔레그램 + 화면 안내").
  이 결정은 [ADR 0026](0026-polite-fetch-layers.md) 결정 5(사람 확인은 풀지 않음)를 고치고, 결정 4(프록시·자택 회선 없음)는 그대로 둡니다.
  결정 8(화면 `/paper/info`)·결정 9(AI 입력에 넣지 않음)는 같은 날 [ADR 0036](0036-info-hub-krx-packet.md)이 고쳤습니다(사이드바 `/info`, 패킷 섹션 `11c_reading` 기본 켬).
- 지키는 방법(시험):
  - 출처·본문·부하: `collector/tests/test_info_sources.py`(RSS 본문 우선·글 페이지는 본문이 없을 때만·실행당 상한, 이미 받은 주소는 다시 받지
    않음, 오래된 글은 넣지 않음, 형식이 다르면 '형식 바뀜', 없는 값은 null), `test_info_waedge.py`·`test_info_naver.py`(합성 표본 파서),
    정책 표의 호스트·하루 예산(`test_info_sources.py`)
  - 개인 IP 금지: `test_polite_switch.py`(스위치가 꺼져 있으면 polite 태스크가 외부를 부르지 않음), CI의 compose 해석 단언(로컬·QA는 `"false"` 고정,
    서버 덧붙임만 켬)
  - 끊김 판정·알림: 수집기 `test_source_state.py`(성공·거부·형식 바뀜·받지 못함·건너뜀이 상태 표에 남는 방식), 백엔드 `SourceAlertJobTest`
    (닫힘·형식 바뀜 2회·받지 못함 3회·오래 못 받음 → 한 통, 회복 한 통, 같은 사건은 다시 보내지 않음), `InfoServiceTest`·`AccessPolicyTest`
  - 사람 확인: `test_sidecar.py`(누르기 호출은 체크박스 함수 하나에만, 입력·키보드 호출 없음, 퍼즐이 뜨면 풀지 않고 "human")
  - 레이더: `test_radar_naver.py`(장중 추정 값은 금액이 없어 쓰지 않음, 확정 값만 억 원으로, 외국인·기관만)
  - 표 소유(ADR 0008): `ArchitectureRulesTest.backendDoesNotWriteCollectorTables`의 수집기 표 목록에 `info_items`·`fetch_source_state`

## 배경

- 사용자 요청(2026-11-11): 해외 투자·경제 블로그 14곳, waedge 뉴스의 시장·거장·해외 블로그 화면, 네이버 투자자별 매매상위(매매동향·외국인·기관)를
  수집기에 더하고, 제목만이 아니라 본문까지, 사람처럼 불규칙한 간격으로 출처에 부담을 주지 않게 받는다. 모의매매 메뉴 아래 '정보 수집' 화면에서
  출처 링크와 함께 본다. 비공식 출처가 형식이 바뀌거나 차단되어 끊기면 텔레그램이나 화면 안내로 알린다. LS증권 API와 pykrx는 지운다.
- 확인한 사실(2026-11-11, 개발 PC에서 출처마다 한 번씩 요청):
  - 블로그 14곳은 모두 RSS·Atom으로 열린다. 12곳은 피드에 본문 전체(`content:encoded` 또는 Blogger 설명)가 있고, Wolf Street는 요약만,
    A Wealth of Common Sense는 일부 글이 짧다. The Irrelevant Investor의 `/feed/`는 HTML이고 실제 피드는 Beehiiv(`rss.beehiiv.com`)에 있다.
    Liberty Street 피드는 100건·약 2.9 MB다.
  - waedge 세 화면은 서버가 완성한 HTML이다. 시장 글은 `/a/<번호>.html` 상세 페이지에 본문이 있고, 거장 화면에는 101명의 견해(강세·중립·약세 점수와 요약)가
    들어 있고, 해외 블로그 화면은 위 14곳의 최근 글에 한국어 제목을 붙인 목록이다. robots.txt는 일반 수집기를 허용하고 AI 학습 봇(ClaudeBot 등)만 막는다.
  - 네이버 새 화면(`stock.naver.com/market/stock/kr/trend/…`)은 JSON API(`/api/domestic/market/trend/daily`·`/trendForeignOrg`)로 표를 채운다.
    장중 순위는 `estimated: true`이고 순매수 금액 칸이 `"0"`이다(주식 수만 있음). 확정 값(`estimated: null`)에는 금액이 있다.
    수급 레이더가 쓰던 옛 네이버 페이지(`finance.naver.com/sise/sise_deal_rank_iframe.naver`)는 HTTP 410이다.
  - 그날 어느 출처도 사람 확인(CAPTCHA·체크박스)을 띄우지 않았다.
  - pykrx는 수급 레이더의 과거 날짜 조회 한 곳, LS증권 API는 레이더 폴백 한 곳에서만 쓰였다(Claude 패킷·한국 규칙 계좌 입력에는 쓰이지 않음).
    LS는 인증 거절(403), pykrx는 KRX 계정 로그인이 있어야 열렸다.

## 결정

1. **출처와 받는 길**: 블로그 14곳은 RSS(피드 주소는 `collector/app/services/info_sources.py` 표 하나), waedge는 세 화면의 HTML과 상세 글,
   네이버는 화면이 부르는 JSON API(매매동향 코스피·코스닥, 외국인·기관 순매수·순매도 상위 코스피·코스닥 — 한 번에 6건). 모두 ADR 0026의
   차단 통과 계층(`app/fetch` — 호스트별 고정 브라우저 지문, 거부되면 서버의 실제 브라우저로 한 번 올라감)과 polite 속도군(비주기 일정)으로 받습니다.
2. **본문**: 피드에 본문이 있으면 피드 본문을 씁니다 — 같은 글을 다시 열지 않는 것이 출처 부하가 가장 적습니다. 피드에 본문이 없거나 짧을 때만
   글 페이지를 열어 본문을 꺼냅니다(출처당 실행 한 번에 최대 4건, 최근 7일 글만). waedge 시장·거장 글은 상세 페이지에서 받습니다(실행당 최대 5건·3건).
   이미 받은 주소(정규화한 주소의 해시)는 다시 받지 않고, 30일보다 오래된 글은 넣지 않습니다. 본문은 글자만 40,000자까지 저장하고 180일 뒤 지웁니다.
3. **불규칙·저부하**: 출처마다 다음 실행을 구간 안에서 무작위로 정합니다 — 블로그 3~8시간(Liberty Street·Damodaran은 6~15시간), waedge 시장 1~3시간·
   거장 8~16시간·해외 블로그 4~8시간, 네이버는 정규장(평일 08:50~15:40) 40~90분·그 밖 3~6시간. 같은 호스트의 요청 사이는 ADR 0026의 4~15초(가끔
   20~45초)이고 호스트별 하루 예산(정책 표)을 넘기지 않습니다. 피드는 `If-None-Match`·`If-Modified-Since`로 바뀐 것만 받습니다(304는 '새 글 없음').
4. **개인 IP를 쓰지 않음**: polite 속도군 전체를 `POLITE_FETCH_ENABLED` 한 스위치로 묶습니다. 로컬·QA compose는 `"false"` 고정(셸·.env 값이 끼어들 자리
   없음), 운영 서버 덧붙임(`compose.vultr.yml`)만 켭니다. 꺼져 있으면 틱이 polite 태스크를 돌리지 않고, 수동 실행도 외부를 부르지 않고 끝납니다.
   출구는 운영 서버 IP 하나이고 프록시·자택 회선·IP 돌려쓰기는 없습니다(ADR 0026 결정 4). 서버 IP가 막히면 그 출처만 물러나 멈추고(결정 6) 알립니다.
5. **사람 확인(ADR 0026 결정 5 개정)**: 실제 브라우저 계층(서버)이 사람 확인 틀을 만나면 **입력 없는 체크박스(Cloudflare Turnstile·hCaptcha·
   reCAPTCHA v2의 '사람입니다' 칸)만 요청 한 번에 한 번** 마우스로 누르고 검사가 지나가기를 기다립니다. 그림·글자 퍼즐, 키보드 입력, 풀이 서비스는
   쓰지 않습니다. 누른 뒤에도 막혀 있거나 퍼즐이 뜨면 지금처럼 그 출처를 12~24시간 닫고 알립니다. 서버 `.env`의 `BROWSER_PRESS_CHECKBOX=false`로 끕니다.
   계층 1(`curl_cffi`)은 누를 수 없어 사람 확인 화면을 받으면 거부로 보고 계층 2로 올라갑니다.
6. **끊김 판정**: polite 태스크마다 수집기 소유 표 `fetch_source_state`에 상태를 남깁니다 — 성공(`ok`), 출처 거부·닫힘(`blocked`), 형식 바뀜
   (`format` — 필수 칸이 없거나 피드·목록에서 글을 하나도 읽지 못함), 받지 못함(`failed` — 404·5xx·전송 실패). 백엔드는 이 표와 `fetch_hosts`를 읽어
   사건을 만듭니다: 닫힘(거부 물러남·사람 확인·포기)은 바로, 형식 바뀜은 연속 2회, 받지 못함은 연속 3회, 오래 못 받음은 마지막 성공이 그 출처 간격 상한의
   3배를 넘을 때입니다.
7. **알림**: 사건마다 운영 봇 텔레그램 한 통(출처·사유·다시 시도 시각, 주소·본문은 싣지 않음)과 풀렸을 때 한 통. 화면은 운영자에게 모든 화면 위에
   안내 띠(닫으면 그 사건이 바뀔 때까지 숨김)를 띄우고, 정보 수집 화면 맨 위에 출처별 상태를 보입니다. ADR 0026의 닫힘 알림(사람 확인·포기만)은
   이 알림으로 넓힙니다 — 보통의 거부 물러남도 알립니다(사용자 지시).
8. **저장과 화면**: 글은 수집기 소유 표 `info_items`(출처·원문 주소·제목·한국어 제목·작성 시각·요약·본문·통과 계층), 거장 견해는 스냅숏
   `info.waedge.gurus`, 네이버는 스냅숏 `info.naver.flows`. 백엔드는 읽기만 하고(ADR 0008) 운영자 전용 경로 `GET /api/info/items`·`/api/info/sources`·
   `/api/info/flows`·`/api/info/gurus`로 내립니다. 화면은 모의매매 아래 `/paper/info`('정보 수집'). 원문 링크를 항상 함께 보이고 '우회 수집'(계층 2)을 표시합니다.
9. **AI 입력에 넣지 않음**: 새 자료는 운영자 화면 전용입니다. Claude 결정 패킷·프롬프트 고정본·한국 규칙 계좌 입력은 바꾸지 않습니다(ADR 0026 결정 10과 같음,
   실험 조건). waedge가 AI 학습 봇을 막는 뜻과도 맞습니다.
10. **레이더의 네이버 단계 교체**: 끊긴 옛 페이지 대신 `trendForeignOrg`(외국인·기관, 당일 `DAY`, KRX 시장)를 씁니다. 장중 추정 순위는 금액이 없어 쓰지 않고
    (0으로 채우지 않음) 다음 단계(토스·누적 이력)로 넘어갑니다. 확정 값의 `accTradeAmount`(원)를 억 원으로, 기준일은 `bizdateTo`로 씁니다. 레이더는
    Daum이 실패할 때만 부르는 폴백이라 공용 세션으로 부릅니다(옛 네이버 단계와 같은 방식, polite 계층 아님).
11. **pykrx·LS 제거**: 레이더 체인은 KIS → Daum → Naver → 토스 → 누적 이력입니다. 과거 날짜는 누적 이력만 봅니다. `KRX_ID`·`KRX_PW`·`LS_APP_KEY`·
    `LS_APP_SECRET`는 더 읽지 않습니다(서버 `.env`의 그 줄은 지워도 됩니다). 수집기 이미지에서 pykrx와 그것만 쓰던 matplotlib 등이 빠집니다.
12. **시험 자료**: 실제 응답 원문은 저장소에 넣지 않고 구조만 흉내 낸 합성 표본을 씁니다(ADR 0026 결정 12, 공개 저장소).

## 이유

- RSS는 출처가 자동 수집용으로 내놓은 길이라 형식이 안정적이고, 본문이 들어 있으면 글마다 페이지를 열 필요가 없습니다. 페이지를 여는 것은 본문이
  없을 때로 한정하는 편이 "부하를 주지 않는 선"에 맞습니다.
- 로컬 스택이 polite 태스크를 돌리면 출구가 사용자 PC의 IP가 됩니다. 스위치를 compose에 고정해 두면 .env를 잘못 옮겨도 로컬에서 켜지지 않습니다.
- 체크박스만 누르는 것은 사용자가 고른 범위입니다. 퍼즐 풀이와 풀이 서비스는 대상 주소를 제3자에게 넘기고, 같은 서버 IP로 받는 다른 수집(RSS·
  TradingView·토스 허용 IP)의 평판을 해칠 위험이 커서 넣지 않습니다.
- 끊김을 수집기 실행 기록에서 추정하면 '새 글 없음'과 '형식 바뀜'을 가를 수 없습니다. 태스크가 판정을 표에 남기면 백엔드는 읽기만 해서 알립니다.
- 네이버 장중 순위는 주식 수 기준이라 레이더의 금액 순위와 단위가 다릅니다. 섞으면 같은 화면에서 다른 단위로 순위가 매겨집니다.

## 대안과 버린 이유

- **글마다 페이지를 열어 본문을 받음**: 피드에 같은 본문이 있는데 요청이 열 배 이상 늘어납니다.
- **waedge 해외 블로그 화면만 받고 원문 블로그는 받지 않음**: 한국어 제목뿐이라 본문이 없습니다. 원문 피드로 본문을 받고 한국어 제목은 주소로 묶어 붙입니다.
- **로컬에서도 수집하되 프록시를 거침**: ADR 0026 결정 4(프록시 없음)와 사용자 지시에 어긋납니다.
- **퍼즐까지 푸는 풀이 서비스**: 위 이유. 사용자도 체크박스만 골랐습니다.
- **네이버 추정 순위를 주식 수 × 현재가로 금액 추정**: 토스 단계가 이미 같은 방식의 추정이고, 시장 전체 순위를 추정 금액으로 바꾸면 이력에 쌓을 수 없습니다.
- **pykrx를 남겨 과거 날짜 조회 유지**: 사용자 지시. KRX 계정 로그인이 필요하고 차단 응답이 잦아 누적 이력으로 충분합니다.

## 결과와 남은 위험

- 서버 IP에서 각 출처가 어느 계층으로 지나가는지는 배포 뒤 실행 기록으로만 압니다. 개발 PC에서는 모두 계층 1(브라우저와 같은 TLS)로 열렸습니다.
- 체크박스 누르기는 Cloudflare Turnstile이 자동화 브라우저를 다시 걸러 효과가 없을 수 있습니다. 그때는 닫힘과 알림으로 끝납니다.
