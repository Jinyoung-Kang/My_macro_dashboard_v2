## 배경

- saveticker.com은 운영 서버 IP를 대역째 막습니다(ADR 0036). 2026-11-11에 대안을 찾았습니다 — 차단을 돌아가는 길(VPN·프록시·다른 IP)은 요청 빈도와
  무관하게 사이트의 거부를 넘는 것이라 쓰지 않기로 했고, 그 사이트가 원출처로 밝힌 곳의 공개 피드를 서버에서 받아 봤습니다(설명형 UA, 피드마다 한 번):
  Financial Juice RSS는 200·100건(제목·링크·시각, 요약 없음, 한산한 시간대 약 11시간 분량, robots.txt 없음), PR Newswire RSS는 200이지만 전체 피드가
  20건·30분 분량에 소형주 보도자료가 대부분, GlobeNewswire는 403(Akamai)이었습니다.
- 정보 수집 화면의 글은 제목이 대부분 영어이고, 본문은 줄 아래에 펼쳐 읽었습니다. 사건 뉴스 RSS는 제목뿐이었습니다.

## 결정

1. **Financial Juice 속보**: 태스크 `info_wire_financialjuice`(polite — 운영 서버에서만)가 RSS 하나를 25~70분에 한 번(구간 안 무작위) 받아 새 줄을
   `info_items`에 넣습니다(출처 `wire.financialjuice`, 종류 `headline`, 본문 없음). 본문이 출처에도 없는 한 줄 속보라 본문을 만들지 않습니다.
   계층 1(브라우저와 같은 TLS)만 쓰고 실제 브라우저로 올리지 않습니다. PR Newswire·GlobeNewswire는 넣지 않습니다.
2. **패킷은 그대로**: 속보와 번역은 운영자 화면 전용입니다. Claude 결정 패킷(11b_events·11c_reading)·프롬프트 고정본은 바꾸지 않습니다 —
   속보 출처는 패킷의 수집 글 출처 목록에 없고, 사건 뉴스 저장본에 더한 `summary` 칸은 패킷이 읽지 않습니다.
3. **사건 뉴스 RSS의 요약**: 피드가 준 요약(description·content)을 글자만 2,000자까지 저장본에 더합니다(`summary`, 줄 때만). 글 페이지는 열지
   않습니다 — 인베스팅닷컴은 자동 요청을 막고, 연합뉴스는 건수가 많은 저작물이며, 정부·중앙은행 보도자료는 요약과 원문 링크로 충분하다고 판단했습니다.
4. **한국어 번역**: 백엔드가 Claude Haiku 5.5를 effort low로 부릅니다(기존 구조화 출력 경로).
   - 제목은 정기 작업이 2분마다 최근 사흘의 영어 제목(수집 글·미국 사건 뉴스)을 40개씩 묶어 미리 번역합니다. 운영 서버에서만 돕니다
     (`INFO_TRANSLATE_ENABLED` — 로컬·QA compose는 `"false"` 고정).
   - 본문·요약은 화면에서 번역 단추를 누를 때만 번역합니다(문단 경계에서 6,000자 조각, 글 하나 40,000자까지).
   - 번역은 백엔드 소유 표 `info_translations`(V35)에 둡니다 — id가 `md5(종류 + ':' + 원문)`이라 같은 글자는 한 번만 번역합니다.
   - KST 하루 원문 150만 자를 넘으면 그날은 번역하지 않습니다. 모의 매매의 Claude 호출 상한과는 따로 셉니다. — 2026-11-15부터 이 상한은 정보 검색 AI 요약([ADR 0041](0041-info-search-watch.md) 단계 6)과 함께 셉니다(요약 몫은 백엔드 메모리라 재기동하면 0부터).
5. **원문 팝업**: 뉴스·글 탭의 글·속보·사건 뉴스 제목을 누르면 받아 둔 원문(본문, 없으면 요약)이 팝업으로 열리고, 번역 단추로 원문과 번역을
   오갑니다(`POST /api/info/translate`, 운영자 전용). 팝업을 열거나 번역해도 수집은 일어나지 않습니다(ADR 0026 — 없는 본문은 원문 링크로 안내).
   거장 견해·수급 표는 이미 한국어이고 전부 보여 팝업을 두지 않습니다.
6. **하루 예산과 실행당 상한**: 호스트별 하루 예산을 2.5배로 올립니다(예: Wolf Street 40 → 100, waedge 80 → 200, 네이버 100 → 250, KRX 40 → 100,
   TradingView 12 → 30). 글 페이지는 실행당 4 → 6건, waedge 상세 글은 5 → 8건·3 → 5건입니다. 간격(태스크마다 구간 안 무작위)·요청 사이 지연
   (4~15초, 가끔 20~45초)·물러남·포기 규칙은 그대로입니다.

## 이유

- 원출처의 공개 피드는 서버 IP로 열리고, 차단을 넘는 수단을 들이지 않아도 됩니다. Financial Juice는 saveticker 속보의 재료라 얻는 정보가 가장 가깝습니다.
- 제목 번역은 목록을 훑는 데 늘 필요하고 글자가 적어 미리 해 둡니다. 본문은 읽을 글만 번역하면 비용과 호출이 읽는 만큼만 듭니다.
- 무료 번역 경로(비공식 구글 번역 주소, 한도가 작은 공개 API)는 금융 용어·티커·속보체 제목에서 품질이 고르지 않고 원문을 제3자 비공식 경로로 보내게
  됩니다. Haiku 5.5는 이미 쓰는 키·SDK·오류 처리로 부를 수 있고 값이 작습니다(입력 100만 토큰 $0.10·출력 $0.50 — 제목만이면 한 달 1달러 미만으로 추정).
- 예산은 상한이라 올려도 평소 요청 수는 간격이 정합니다. 올린 뒤에도 가장 잦은 간격으로 하루 내내 돌았을 때의 요청 수보다 조금 큰 수준입니다.

## 대안과 버린 이유

- **saveticker를 VPN·프록시·다른 클라우드 IP로**: 사이트의 차단을 넘는 것입니다. 운영사에 서버 IP 허용이나 피드 제공을 묻는 길은 남아 있습니다.
- **속보를 사건 뉴스 피드 목록(`news.FEEDS`)에 더함**: 패킷 사건 섹션에 하루 수백 줄이 들어가 실험 조건이 바뀌고, 그 태스크는 로컬 스택에서도 돌아
  출구가 PC의 IP가 됩니다.
- **팝업을 열 때 글 페이지를 받아 옴**: 화면 조회가 수집을 일으키면 비주기 일정과 하루 예산을 건너뜁니다(ADR 0026).
- **모든 본문을 미리 번역**: 읽지 않는 글까지 번역해 비용이 수십 배가 됩니다.

## 결과와 남은 위험

- Financial Juice는 RSS 이용 조건을 밝힌 문서를 찾지 못했고 공식 지원 피드가 아닙니다. 끊기면 다른 출처처럼 물러나 멈추고 알립니다.
- 바쁜 날(주요 지표 발표)에 70분 사이 100건을 넘게 내면 그 사이 줄을 놓칩니다 — 실행 기록의 '누락 가능'으로 보고, 잦으면 간격을 줄입니다.
- 번역은 모델이 옮긴 것이라 숫자·고유명사가 틀릴 수 있습니다. 팝업에 원문을 함께 두고 그 사실을 적습니다.
- 서버의 `AI_ENGINES` 허용 목록에 Haiku 엔진이 없으면 번역은 나가지 않고 사유를 보입니다.
- 번역 비용은 Anthropic 사용량에 모의 매매와 함께 잡힙니다. 정보(메커니즘) 탭에 오늘 번역한 글자 수를 보입니다.

## 개정 (2026-11-12)

사용자 지시: "번역 기능에 Gemini API를 활용", "제목을 무조건 미리 번역하지 않고 원문 그대로, 제목마다 번역 단추", "시각을 한국 시각(KST) 기준으로".

1. **엔진**: `dashboard.info.translate.engine`(환경변수 `INFO_TRANSLATE_ENGINE`, 기본 auto) — `GEMINI_API_KEY`가 있으면 **1순위 Gemini**
   (`gemini-3.5-flash`, 사고 낮게 — `INFO_TRANSLATE_GEMINI_MODEL`로 바꿈), 실패하면(한도 초과·오류·45초 시간 초과) **2순위 Claude Haiku**·effort low로
   넘어갑니다(사용자 지시: "Gemini 1순위·Haiku 2순위, Gemini는 무료 한도 안에서만, 너무 싼 모델은 쓰지 않음"). 번역 행에는 실제로 옮긴 모델을 남깁니다. 키가 없으면 Claude Haiku만, `gemini`·`claude`로 고정하면 그 엔진만 부릅니다.
   1순위 모델이 실패하면(붐빔 503·한도 초과·시간 초과·빈 응답 등 종류를 가리지 않고) 한 등급 아래 Gemini(`gemini-3.5-flash-lite`)를 한 번 불러
   보고, 그것도 안 되면 Claude Haiku로 갑니다(같은 날 사용자 지시 — 서버에서 무료 등급의 503을 실제로 봄). 키·결제 문제만은 같은 키라 아래 모델을
   부르지 않습니다. 쉬는 시간(10분)은 모델마다 따로라, 1순위가 한도에 걸려도 아래 모델이 받습니다. 아래 모델은 인명을 바꿔 옮긴 적이 있어 1순위가
   될 때는 쓰지 않고, 번역 행·화면에 실제로 옮긴 모델 이름을 남깁니다.
   Gemini는 SDK를 더하지 않고 REST(`generateContent`, 키는 머리글)로 부릅니다(`feature/info/GeminiClient`).
   무료 등급은 결제를 연결하지 않은 프로젝트의 키일 때입니다 — 그 등급의 입력은 Google의 제품 개선에 쓰일 수 있습니다(번역하는 글은 공개된 기사·블로그).
2. **제목**: 미리 번역하지 않습니다 — 정기 작업(`InfoTranslateJob`)과 `INFO_TRANSLATE_ENABLED`를 지웠습니다. 목록은 원문 제목을 그대로 보이고
   (출처가 붙인 한국어 제목 — waedge 해외 블로그 — 은 아래에), 한글이 없는 제목마다 번역 단추를 둡니다. 누른 제목만 번역하고 저장합니다.
3. **시각**: 서버는 이미 KST로 내리고 있었지만 화면이 'KST'를 떼고 보였습니다. 글·속보·사건 뉴스·팝업·네이버 순위 시각에 KST를 적습니다.
4. **확인한 사실**(2026-11-12, 개발 PC에서 키로 호출): 처음 키는 생성 호출이 402(선불 크레딧 소진 — Gemini 앱 구독과 API 과금은 별개)였고,
   사용자가 새 키를 넣은 뒤 같은 요청이 200으로 번역을 돌려줬습니다. 같은 제목 여섯 개를 실제 지시문으로 견줬을 때 flash-lite는 인명 하나를 다른
   사람으로 바꿔 옮겼고(Healey → 리브스) 3.5 Flash는 모두 맞아 기본 모델을 Flash로 정했습니다.
5. 이미 저장된 번역(Claude가 옮긴 제목 약 800건)은 표에 남아 같은 제목의 번역 단추를 누르면 모델을 부르지 않고 그대로 나옵니다.
- 시험: `GeminiClientTest`(키 없음·닿지 못함·응답 읽기·막힘/잘림), `InfoTranslatorTest`의 엔진 선택, `InfoHub.test.tsx`(제목 원문·제목별 단추·KST),
  `info.test.ts`.

## 덧붙임 (2026-11-12, 5차 리뷰)

- **QA-403 — 저장본을 다시 읽을 때의 모델 이름**: 개정 1의 "번역 행·화면에 실제로 옮긴 모델 이름을 남김"이 저장본만으로 끝난 응답에서는 지켜지지 않았습니다(응답의 `model`은 이번에 부른 모델이라 null). 번역 응답에 `models`(이 번역을 옮긴 모델 전부 — 번역 행에서 읽음, 제목 먼저·본문 조각 순서)를 더하고, 원문 팝업의 안내가 그 이름을 모두 보입니다. `model`의 뜻은 그대로입니다. 저장된 번역을 지우고 다시 번역하는 길은 새 기능이라 두지 않았습니다.
- **QA-405 — Gemini 응답 판정**: (1) 종료 사유가 비었거나 정상 종료(STOP)일 때만 성공으로 봅니다 — 안전·인용 등으로 끊긴 응답은 글이 일부 있어도 실패(REFUSAL)입니다. (2) 응답을 읽는 일(JSON 해석·쓸 번역이 있는지)을 엔진 호출 안으로 옮겨, 성공으로 답한 엔진의 형식 밖 응답도 실패(PARSE)로 보고 다음 순위(아래 Gemini → Claude Haiku)로 넘어갑니다 — 개정 1의 "실패의 종류를 가리지 않고 넘어감"이 이 경우에는 지켜지지 않아, 그 글은 누를 때마다 같은 길로 실패했습니다. PARSE는 그 모델을 쉬게 하지 않습니다. (3) HTTP 400(요청을 받지 않음)을 BAD_REQUEST로 따로 가르고 쉬는 사유에 넣었습니다(10분, 모델마다 따로) — 예전에는 조각마다 두 Gemini 모델을 헛되이 부른 뒤 Haiku로 갔습니다. 버린 대안: 같은 모델 재시도(무료 한도만 씀). 감수한 것: 그런 응답에서 유료 Haiku 호출이 늘 수 있습니다(하루 글자 상한 안). Gemini가 실제로 이런 응답을 주는지는 확인하지 못했습니다.
- **QA-406 — 본문을 JSON 값으로**: 본문 조각을 `<원문>` 꼬리표 사이에 그대로 넣어 보내던 것을 제목처럼 JSON 값(`{"text": …}`)으로 바꿨습니다. 수집한 글에 닫는 꼬리표와 지시문이 있으면 자료 구간 밖 글처럼 보일 수 있었습니다(지시는 시스템 프롬프트에만 있고 응답은 스키마로 한 칸이며, 번역은 화면에 글자로만 보이고 패킷으로 가지 않아 영향은 작았습니다). 시스템 프롬프트의 입력 설명 한 줄을 그에 맞췄습니다. 입력 모양이 번역 품질에 주는 영향은 실제 엔진으로 확인하지 못했습니다(시험은 대역 — QA로 넘김).
