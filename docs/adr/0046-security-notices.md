## 배경

이 프로젝트는 Vultr 서버 한 대에서 컨테이너 여섯(postgres·backend·frontend·collector·browser·caddy)으로 돕니다. 서버의 자동 보안 업데이트와 재부팅 점검(ADR 0023)은
있지만, "지금 알려진 취약점 가운데 이 환경에 아직 남은 것이 무엇인가"를 한곳에서 보는 화면은 없었습니다. KISA 보호나라 보안공지 게시판은 한국어로 제품별 취약점과
영향받는 버전·해결 버전을 정리해 올립니다.

조사로 확인한 사실이 방향을 정했습니다.

- 보호나라 제품 공지 본문에는 `취약점 | 제품명 | 영향받는 버전 | 해결 버전` 4열 표가 고정으로 있어 AI 없이 읽을 수 있습니다. 표가 없는 공지(공고·행사 등)도 섞여 있습니다.
- 어려운 쪽은 "무엇이 몇 버전으로 깔려 있는가"입니다. 이미지 태그가 떠 있어(`postgres:16-alpine`, `caddy:2-alpine`, Chrome 미고정) 실제 버전은 서버에서만 알 수 있고,
  컨테이너에는 `docker.sock`·호스트 경로 마운트가 없습니다.
- 배포판 패키지(apt·apk)는 옛 버전 번호에 보안 패치만 넣으므로(Ubuntu `3.0.13-0ubuntu3.16` 꼴) 공지의 상류 버전 표와 비교하면 틀린 답이 납니다.
- 단계 0(2026-11-21 01:55 KST, 서버에서 읽기만): 보호나라 목록 1쪽이 서버 수집기의 공용 세션으로 200. `apt list --upgradable`의 저장소 이름은 `이름/저장소`이고
  Ubuntu Pro ESM 저장소는 `<코드명>-infra-security`·`<코드명>-apps-security`(esm.ubuntu.com 저장소 디렉터리에서 확인) — 보안 여부는 저장소 이름이 `-security`로 끝나는지로 가립니다.

## 결정

1. **버전 목록은 호스트 스크립트 하나(`scripts/vultr/inventory.sh`)가 전부 모읍니다.** 호스트 항목(OS 패키지·커널·Docker·Compose·Tailscale·apt 보류)은 호스트에서만 읽히고,
   컨테이너 안 항목(postgres 서버 버전, 백엔드 JDK와 jar 의존성, 프런트 Node와 `node_modules`, 수집기 Python 패키지, 브라우저 Chrome, caddy, 컨테이너 OS 패키지)은
   `docker compose exec`로 읽습니다. 컨테이너가 스스로 보고하는 길을 섞으면 표·쓰는 곳·기준 시각이 셋으로 갈립니다. 구역마다 실패를 따로 잡아 나머지는 보내고,
   구역별 상태(`ok`·`failed`·`skipped`)를 함께 넘깁니다. 호스트 구역은 서버에서만 모읍니다(재부팅 점검과 같은 판별). `apt-get update`는 하지 않습니다(목록 나이를 함께 넘김).
2. **넘기는 길은 `docker compose exec -T collector python -m app.inventory`의 표준입력입니다.** `deploy.sh`의 `init_schema`와 같은 길이라 새 HTTP 쓰기 경로·토큰 다루기가
   없고, 쓰는 코드가 `app/store.py` 한 곳입니다(ADR 0008). 입력은 탭 구분 줄(머리·`section`·`component`·`pending`)이고, 검증에 실패하면 아무것도 쓰지 않습니다.
   받으면 표 셋을 한 트랜잭션으로 통째로 바꿉니다(늘 '마지막으로 모은 한 벌').
3. **공지 수집은 flex 속도군·공용 세션입니다**(위 '고치는 결정'). 한 실행은 목록 1쪽 → 처음 본 글 넣기 → 상세 최대 8건(요청 사이 3~6초). 평소 간격 3~6시간,
   처음 90일을 메우는 동안만 20~40분. RSS는 쓰지 않습니다 — 90일 메우기에 목록 해석기가 어차피 필요하고, RSS는 날짜가 비표준이라 해석기가 하나 더 생깁니다.
4. **출처 상태를 남깁니다**(`store.note_source_state`). flex 태스크지만 끊김·형식 바뀜 알림(`SourceAlertJob`)과 수집 현황 화면이 새 코드 없이 붙습니다.
   표 틀이 깨지면(`info_text.ShapeError`) 형식 바뀜입니다.
5. **판정은 백엔드가 읽을 때 계산합니다**(공지 행 × 버전 목록의 순수 함수 — 저장하지 않음). 저장된 판정이 낡을 일이 없고, 별칭 표를 고치면 바로 반영됩니다.
6. **판정은 넷이고, 모르는 것을 안전으로 표시하지 않습니다.** 공지 판정은 행 판정의 최댓값(해당 > 확인 필요 > 패치됨 > 무관).
   - 해당: 설치 버전이 영향 구간 안. 배포판 패키지는 apt 보류(보안) 목록에 있을 때만.
   - 패치됨: 같은 계열의 행이 있고 설치 버전이 해결 버전 이상(16.x 행만 있는데 17.x를 쓰면 확인 필요).
   - 확인 필요: 제품은 맞는데 판정할 수 없음 — 사유 코드 `PARSE_FAILED`(버전 칸 해석 실패)·`OUT_OF_TABLE`(같은 계열 행 없음)·`DISTRO_NO_PENDING`(배포판 패키지인데 보류
     목록에 없음 — 패치를 받았는지 모름)·`NO_INVENTORY`(버전 목록 없음·그 구역 실패)·`CONDITION_NOTE`(표 밖 `※` 조건 문장)·`NO_VERSION_TABLE`(표가 없는 공지에 별칭이 나옴)·
     `NAME_MATCH`(이름만 맞음)·`VENDOR_DIFFERS`(제조사가 다름).
   - 무관: 쓰지 않는 제품. 이름이 겹치는 다른 제품(PostgreSQL↔pgAdmin, Next.js↔Nextcloud, Java↔JavaScript 등)은 별칭 표의 제외 규칙으로 무관에 둡니다.
7. **알림은 알림함 + 텔레그램 운영 봇, 공지당 한 번입니다.** 백엔드 작업(15분)이 판정을 계산해 기록에 없는 '해당' 공지를 알림함 사건(`SECURITY_NOTICE`)으로 넣고 운영 봇으로
   보냅니다. 기록 표 `security_alerts`를 따로 두어 텔레그램이 실패하면 다음 주기에 다시 보냅니다(`source_alerts`와 같은 모양 — `alert_events.event_key`만으로는 재시도를 못 함).
   글에는 제품 이름·CVE 건수·화면 링크만 넣고 설치 버전은 텔레그램과 로그에 넣지 않습니다.
8. **새 환경 변수·스위치는 없습니다.** flex 태스크는 스위치가 없고, 버전 목록은 cron을 건 곳(서버)에서만 생깁니다 — 버전 목록이 없는 곳(로컬·QA)은 제품이 맞는 공지가
   모두 확인 필요(`NO_INVENTORY`)이고 알림이 0건입니다.
9. **세부 결정**(계획 승인 때 함께): (1) 표로는 해당인데 표 밖 `※` 조건 문장이 있으면 해당으로 두고 '조건 문장 있음'을 함께 표시, 패치됨 + `※`는 확인 필요로 내림 ·
   (2) 처음 90일을 메울 때 한 주기에 새로 해당이 된 공지는 텔레그램 한 통에 묶음(공지마다 한 번은 그대로) · (3) 제조사가 다른 제품(Oracle Java SE 공지와 Temurin 등)은 번호가
   구간 안이어도 확인 필요(`VENDOR_DIFFERS`) · (4) '확인함' 표시(쓰기 경로)는 범위 밖 — 사유별 거르기만 · (5) 메뉴는 더보기 '묶음 없음'의 `/connections` 다음, 이름 "보안 공지",
   주소 `/security`, 운영자 전용(API 세 경로 모두 `AccessPolicy` 운영자, 쓰기 경로 없음).
10. **보호나라 글의 이용 조건.** 2026-11-21 확인: 보호나라 사이트에는 저작권 정책·이용약관 페이지 링크가 없고 하단에 "Copyright(C) 2023 KISA. All rights reserved." 한 줄만
    있으며, 보안공지 목록 화면에 공공누리 표시가 없습니다. `robots.txt`에는 `Disallow` 줄이 없습니다(검색 로봇 둘에 목록 경로를 허용하는 줄만). 그래서 이 기능은 개인·비공개·
    비상업 운영자 화면에서만 글을 보이고([ADR 0035](0035-info-collection.md)의 출처 원칙과 같음), 늘 원문 링크를 함께 둡니다. 글 본문·표를 공개 저장소(시험 고정본·문서·QA 씨앗)에 옮기지 않고
    시험에는 구조만 흉내 낸 합성 HTML을 씁니다. 요청 간격(상세 사이 3~6초, 평소 3~6시간)을 지킵니다.

## 대안과 버린 이유

- **컨테이너마다 스스로 버전을 보고**: 표·쓰는 곳·기준 시각이 셋으로 갈리고, 호스트 항목은 어차피 못 읽습니다.
- **수집기에 새 HTTP 받기 경로**: 토큰·인증·크기 제한을 새로 다뤄야 합니다. `docker compose exec`의 표준입력이면 서버 셸 권한이 곧 쓰기 권한입니다.
- **공지의 버전 표만으로 배포판 패키지 판정**: Ubuntu·Alpine은 옛 번호에 패치를 넣어 늘 '해당'으로 틀립니다. apt 보류 보안 목록을 근거로 씁니다(컨테이너 안 apk·dpkg는
  보류 목록이 없어 늘 확인 필요).
- **AI로 공지 해석**: 표가 고정이라 필요 없고, 판정이 흔들리면 안 되는 자리입니다(사용자 결정).
- **OSV 등 취약점 DB 대조**: 범위가 커지고 출처가 늘어납니다(사용자 결정 — 이번 범위 밖).
- **RSS**: 위 결정 3.
- **판정을 저장**: 별칭·해석 규칙을 고칠 때마다 다시 계산해야 하고 낡은 판정이 남습니다.

## 결과와 남은 위험

- 보호나라는 이 스택의 일부만 다룹니다(최근 공지 30건 가운데 겹친 것은 PostgreSQL·Node.js·OpenSSH 정도). 이 화면이 '해당 없음'이어도 Spring·Caddy·Docker·Tailscale이
  안전하다는 뜻은 아닙니다 — 화면에 이 한계를 한 줄로 적습니다.
- 배포판 패키지 공지(OpenSSL·curl·커널)는 apt 보류 목록에 없으면 계속 확인 필요로 쌓입니다. 컨테이너 안 apk·dpkg는 보류 목록이 없어 늘 확인 필요입니다.
- 서버의 실제 버전 목록은 운영 DB에만 둡니다. 저장소가 공개이므로 시험 고정본·QA 씨앗·문서·커밋 메시지·로그에는 가짜 값만 씁니다.
- 서버 IP에서 보호나라가 막히면 차단 통과 계층(polite)으로 옮겨야 합니다(단계 0에서는 열림).
- 범위 밖: 고쳐진 공지의 상세 다시 받기, 배포판 버전을 직접 적은 행(`Alpine Linux 3.24 (openssh)` 꼴)의 apk 버전 비교, 버전 목록이 오래됐을 때의 텔레그램 알림
  (화면에는 2일 넘으면 경고), '확인함' 표시.
