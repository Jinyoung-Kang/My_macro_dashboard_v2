## 배경

v1(2026-10-25에 v3에서 갈라짐)은 AWS 운영본(ADR 0019)으로 🧪 모의 알고리즘 매매(미국)를 돌립니다. 다음 일은 화면 전면 개편(17개 경로 → 다섯 탭),
한국 증시 책, 외부 오픈소스의 정의·출처 채택, 그리고 AWS 교체입니다. 운영 중인 v1에서 바로 바꾸면 화면이 여러 날 반쯤 바뀐 채로 돌고, 한국 책의
스키마·패킷 변경이 미국 책 실험(ADR 0018)을 흔듭니다.

## 결정

1. **fork**: v1을 전체 이력으로 clone한 `My_macro_dashboard_v2`(GitHub 공개 저장소). 백엔드·수집기·DB 스키마는 이어받고(마이그레이션 번호도 V13부터)
   프런트엔드만 새로 씁니다. API 경로는 바꾸지 않습니다(docs/API.md가 계약).
2. **로컬 동시 가동**: 3002/8082/8002/5434, QA 스택 `my_macrodash_v2_qa`(13002/18082/18002/15434, 프록시 18890), 세션 쿠키 `my_macro_v2_session` —
   v3(3000/…)·v1(3001/…)과 같은 맥에서 함께 돕니다. 데이터는 v1 백업 → v2 복원(ADR 0003)으로 이어받고 볼륨은 복사하지 않습니다.
3. **모의 매매 상태는 계속 AWS v1 한 곳**: 로컬 v2는 `PAPER_ENABLED=false`. 교체 때 상태를 한 번만 옮기고 v1을 바로 멈춥니다.
4. **이름**: 기존 책은 "모의 알고리즘 매매(미국)". 테이블·계좌 코드는 그대로 두고 `paper_books`에 `market`·`currency`(V13, 기본 `US`·`USD`)를 더합니다.
5. **한국 책**(2단계): 1억 원 × 4계좌(규칙·Claude·KODEX 200·60/40), 규칙 계좌는 수급 신호, 재선정 월 1~2회 — 명세 초안을 확정한 뒤.
6. **Claude 호출 상한 20**: 설정 `apiDailyCallCap` 기본 20(코드 최대 50). 1회 약 $0.09로 어림하면 하루 최대 약 $1.8. 추정 비용은 지금처럼 `paper_api_usage`에 쌓입니다.
7. **봇 차단 우회의 허용 범위**(D29 개정): 브라우저 없이 되는 출처를 먼저 쓰고, 우회로 받은 자료도 출처·수집 시각을 적으며, 상주 우회 서버는 두지 않습니다
   (필요할 때만 뜨는 one-shot). 서버 크기(t4g.large) 결정(V2) 뒤 5단계에서 합니다.
8. **AWS 교체**: 같은 EC2 `my-macro-app`, 토요일 창(미국 세션 없음), 서버의 v1 백업 → v2 복원. 되돌리기는 v1 폴더·볼륨을 남겨 두고 v2 `make down` → v1 `make up`(계획서 §5).
9. **외부 코드**: 정의·출처·안전 패턴만 옮기고 코드째 들이지 않습니다(OSS 목록). 라이선스는 따지지 않습니다(V8 — 개인·비영리).

## 이유

- **fork**: 검증된 정확성 규칙(ADR 0001~0019, PRINCIPLES, 시험 약 2,800개)을 다시 쓸 이유가 없고, 화면은 패턴 자체가 바뀌어 고쳐 쓰기보다 새로 쓰는 편이 빠릅니다.
- **운영본과 분리**: v1이 계속 돌아 개편 중에도 모의 매매 기록이 끊기지 않습니다.
- **상한 20**: 결정·미리보기·프레임 제안·주간 복기에 한국 책 결정까지 더하면 6으로는 하루 몫이 모자랍니다.
- **우회 범위**: 사용자 결정(V5). 다만 서버 4 GiB에 상주 브라우저는 무겁고, 출처를 밝히지 않으면 우회 값과 공식 값을 화면에서 구분할 수 없습니다.

## 대안과 버린 이유

- **처음부터 새로 쓰기**: 백엔드·수집기의 규칙과 시험을 잃습니다.
- **v1에서 브랜치로 진행**: 운영본 저장소에 반쯤 바뀐 화면·스키마가 섞이고, 서버 배포(main fast-forward)가 막힙니다.
- **새 EC2에서 교체**: 인프라·비용이 두 배가 되고 모의 매매 상태를 두 서버 사이에서 옮겨야 합니다. 같은 EC2·폴더 이름 규칙이 더 단순합니다.
- **v2를 private으로**: v1이 이미 공개 저장소라 얻는 것이 없습니다(사용자 지시로 바꿈).

- 갈라진 뒤 v1에 들어가는 긴급 수정은 v2로 손으로 옮겨야 합니다(같은 수정을 두 저장소에).
