# 0024. 화면 실시간 시세 — 저장하지 않고 서버가 고른 주기(5초~3시간, 기본 1시간)마다 밀어 줌(SSE), 출처 순서는 미국 네이버 → Yahoo·국내 네이버 → 다음 → 토스 1분봉, 표시 전용

- 상태: 채택 (2026-11-03, 사용자 요청과 승인 — "시세를 최대한 실시간에 가깝게", 계획 승인 시 "기본 주기 1시간", "서버가 값을 밀어 주는 방식(SSE)").
  1단계: 모의 매매 장중 카드·보유 표·종목 상세(`/s/<시장>/<코드>`)와 모의 매매 TOP 단추. 2단계: [시장] 메뉴(`/macro` 카드·`/sector`) — 1단계 확인 뒤.
- 지키는 방법:
  - `collector/tests/test_live_prices.py`: 요청 형식('US:심볼'·'KR:6자리', 60개까지), 출처별 파싱(고정 응답), 앞 출처가 못 준 종목만 다음 출처에, Yahoo 래치가
    닫혀 있으면 묻지 않음·Yahoo가 거부하면 yfinance와 같은 래치 이름(`http.YAHOO_HOST`)을 닫음, Yahoo는 공용 세션과 다른 브라우저 표시, 3초 캐시, 경로 400.
  - `LivePriceServiceTest`: 종목·주기 검사(400), store_only·무응답은 `available:false`, 받은 종목이 모두 장이 닫혀 있으면 다음 보내기 5분 이상, 연결 20개 상한(429),
    SSE 구독이 바로 `prices` 이벤트(`text/event-stream`). `AccessPolicyTest`·`RouteInventoryTest`(문서·QA routes.json — SSE는 퍼저 제외).
  - 화면: `lib/__tests__/livePrices.test.ts`(선택지·기본 1시간·예전 분 단위 값 옮겨 읽기·장중 저장본 1분 하한), `hooks/__tests__/useLivePrices.test.tsx`(SSE 주소·쿠키,
    탭을 숨기면 닫고 다시 이음, 끄기는 한 번만 읽기, 주기 공유), `lib/__tests__/paperLive.test.ts`(실시간 값으로 종목 줄 다시 셈), 장중 카드 화면 시험(QA-154~163 그대로),
    `components/__tests__/ScrollTopButton.test.tsx`.

## 배경

장중 시세는 지금까지 DB 저장본을 거쳤습니다 — 수집기 태스크(`paper_live_us`·`paper_live_kr`, 1분봉)가 스냅샷을 쓰고, 백엔드가 그 저장본을 60초보다 자주 새로 받지
않으며(`Datasets.MAX_AGE_LIVE`, Yahoo 429 때문) 같은 태스크 요청에는 30초 쿨다운이 있습니다. 그래서 화면을 5초마다 읽어도 값은 1분에 한 번밖에 바뀌지 않았습니다.
사용자는 모의 매매와 시장 메뉴의 종목 가격이 5·10·30초 주기로 움직이기를 원했고, 출처로 한국은 토스 API·다음·네이버, 미국은 야후·인베스팅·트레이딩뷰·구글
파이낸스를 들었습니다(봇 차단이 있으면 우회해도 된다고 함).

## 결정

1. **저장하지 않는 길을 새로 냅니다**: 화면 → 백엔드 `GET /api/live/prices`·`/api/live/prices/stream`(feature.live) → 수집기 `GET /live/prices`(3초 메모리 캐시)
   → 출처. 테이블·스냅샷을 만들지 않습니다(검색 상세의 `/live/quote`와 같은 선례 — [decisions.md 2026-11-01](../decisions.md)).
2. **서버가 밀어 줍니다(SSE)** — 사용자 결정. 구독하면 바로 한 번, 그 뒤 고른 주기마다 `prices` 이벤트. 25초마다 주석 줄(하트비트), 연결은 주기 + 5분 뒤 끝나고
   브라우저(EventSource)가 다시 잇습니다. 받은 종목이 모두 장이 닫혀 있으면(CLOSED·모름) 다음 보내기는 5분 이상 뒤. 동시 연결 20개 상한. 화면은 탭을 숨기면
   연결을 닫고 다시 보이면 다시 잇습니다(보지 않는 동안 받지 않음 — ADR 0020의 '화면을 볼 때만').
3. **주기는 하나**: 끄기·5·10·30초·1·2·5·10·15·30분·1·3시간, **기본 1시간**(사용자 결정). 이 브라우저에 기억(`live.priceRefreshSeconds`)하고 장중 카드·보유 표·
   종목 상세가 같은 값을 씁니다. 예전 장중 카드의 분 단위 값(`paper.liveRefreshMinutes`)은 한 번 옮겨 읽습니다. 끄기는 화면을 열 때 한 번만 읽습니다.
4. **출처 순서**(앞 출처가 못 준 종목만 다음 출처에):
   - 미국: 네이버 해외주식 polling(로이터 코드 — 자동완성으로 찾아 하루 캐시, 여러 종목 한 번에) → 네이버가 못 주는 종목(지수 ^…·환율 =X 등)은 Yahoo spark
     (`v7/finance/spark`, 한 번에 20종목). 처음에는 Yahoo가 먼저였으나 배포 뒤 실측에서 Yahoo spark가 1분 넘게 같은 값이라 바꿨습니다(QA-166).
   - 국내: 네이버 polling(`domestic/stock/<코드,…>`, 여러 종목 한 번에, 거래 시각·NXT 시간 외 포함) → 다음(`/api/quotes/A<코드>`, Referer) → 토스 1분봉(분 단위).
   - 출처 거부(403·429·봇 차단)는 공용 세션의 5분 래치를 따르고 다음 출처로 넘어갑니다. Yahoo는 yfinance 경로와 같은 래치 이름을 함께 씁니다(같은 한도).
5. **표시 전용**: 장부(체결·스탑·순자산 줄·통계·Claude 입력)는 이 값을 쓰지 않습니다 — 그쪽은 기존 저장본(60초 하한)입니다. 장중 카드의 계좌 숫자(지금 값)도
   장중 저장본 그대로이고 1분보다 짧게 다시 읽지 않습니다. 종목 줄의 가격·평균 단가 대비·직전 종가 대비만 실시간 값으로 다시 셉니다. 보유 표는 장부 칸을 두고
   '실시간' 칸을 더합니다.
6. **응답**: 종목마다 가격·전일 종가·등락·통화·거래 시각(ISO UTC)·장 상태(OPEN·PRE·POST·CLOSED)·출처·시간 외 가격. 모르는 값은 null(0으로 채우지 않음),
   받지 못한 종목은 `missing`, 출처별 실패는 `errors`. 화면은 출처·거래 시각을 늘 함께 보입니다.
7. **접근**: 회원(검색 상세 시세와 같은 등급). 종목 형식·개수(60)·주기를 백엔드와 수집기가 각각 검사합니다. `store_only` 배포는 부르지 않습니다.
8. **종목 상세로 이동**: 장중 카드·보유 표의 종목을 누르면 `/s/<시장>/<코드>`(기존 검색 상세), 그 화면의 가격도 같은 주기로 움직입니다. 모의 매매 화면에는
   400px 넘게 내려가면 나타나는 'TOP' 단추(본문·창 모두 맨 위로).

## 대안과 버린 이유

- **화면이 묻기(폴링)**: 처음 계획이었으나 사용자가 SSE로 정했습니다. 출처를 묻는 횟수는 같고(3초 캐시), 응답이 오가는 시간만큼 빠릅니다.
- **DB 저장본에 실시간 값 쓰기**: 60초 하한·30초 쿨다운을 풀어야 하고 5초마다 스냅샷을 씁니다 — 장부가 그 저장본을 읽어 표시 값과 장부 값이 섞입니다.
- **증권사 실시간 웹소켓(KIS·LS — 키는 있음)**: 공식이고 더 빠르지만 요청한 출처 밖이고 상주 연결·종목 등록 관리가 따릅니다. 필요해지면 같은 `/live/prices` 뒤에 붙일 수 있습니다.

## 결과와 남은 위험

- 장기 호출 한도는 모릅니다 — 실측은 1분(5초×12)뿐입니다. 5초 주기로 화면을 오래 열어 두면 출처 하나당 시간당 약 720번입니다. 기본을 1시간으로 두고, 거부되면
  5분 쉬고 다음 출처로 넘어가며, 장이 닫혀 있으면 5분 이상 간격입니다.
- Yahoo가 공용 세션의 브라우저 표시에 429를 주는 것은 이번에 처음 확인했습니다(다른 Yahoo 수집은 yfinance라 영향 없음). 표시를 바꾸면 다시 확인합니다.
- 한국 장중 지연(거래 시각 대비)은 장이 닫혀 있을 때 실측해 장중 확인이 남았습니다(2026-11-03 09:05 KST 예정 — 결과를 여기 덧붙임).
