# 0029. ISA 계좌: 연결되지 않은 다른 증권사 계좌를 규칙 계좌 메커니즘으로 '지시 + 직접 매매' — 장부와 지시만, 주문 없음, 지시 알림만 종목·수량 허용

- 상태: 채택 (2026-11-06, 사용자 요청과 승인 — "이 프로젝트와 연동하지 않은 다른 증권계좌(현금 1,000만 원)를 한국 '규칙 계좌' 메커니즘으로 운용. [한국]-[실제 계좌] 옆에 'ISA 계좌'.
  화면을 보거나 텔레그램 알림으로 내가 직접 매매", 질문 답 "지시대로 자동 기록 + 다르면 고침 · ISA만 종목·수량 포함 · 밤 결정 직후 + 아침 08:00 · 안내 목록대로 산 것으로 시작", 계획 승인).
  계약은 [명세](../specs/2026-11-06-isa-manual-account.md).
- 지키는 방법: 백엔드 `ManualAccountPlannerTest`·`ManualAccountLedgerTest`·`ManualAccountNoticesTest`·`ManualAccountServiceDbTest`·`ManualAccountJobDbTest`·`ManualAccountPaperReadsTest`(지시 계산·자동 기록·알림 글에 금액 없음), `ArchitectureRulesTest.realtradeIsIsolated`(허용 목록에 `store.ManualAccountStore`),
  `AccessPolicyTest`(운영자 전용), 화면 `isaBoundary.test.ts`·탭은 KR만.

## 배경

운영자는 이 프로젝트와 연결하지 않은 다른 증권사의 ISA 계좌도 한국 규칙 계좌 메커니즘으로 굴리되, 주문은 직접 내고 싶어 했다. 그 증권사에는 API 연결이 없다.
토스 계좌는 [ADR 0028](0028-real-trade-mirror.md)로 자동 매매를 한다.

## 결정

1. **장부와 지시만**: 시스템은 ISA 계좌의 장부(입출금·매수·매도·조정 행)를 들고, 규칙 계좌의 밤 결정 뒤 다음 시가의 매매 지시(종목·방향·수량)를 계산해 화면과 텔레그램으로 알린다.
   증권사 연결·계좌 조회·주문은 없다 — 돈을 움직이는 것은 사용자다.
2. **계산은 실제 매매와 같다**: 목표 비중 = 규칙 계좌의 시가 뒤 예상 비중(`PaperMirrorService.openTargets`), 목표 수량 = floor(비중 × ISA 평가액 ÷ 기준가), 차이 1주 이상 & 평가액 1% 이상만,
   책에 없는 보유는 전량 매도(`RealTradePlanner.sync` 재사용).
3. **체결은 지시대로 자동 기록 + 고침**(사용자 결정): 그날 밤 모의 장부와 같은 시가 사다리로 장부에 적고, 사용자가 실제 체결과 다르면 화면에서 고친다. 고친 장부가 다음 지시의 기준이다.
4. **텔레그램 예외**(사용자 결정): ISA 지시 알림에 한해 종목 코드·이름·수량을 넣는다. 금액·평가액·현금은 넣지 않는다. 토스 자동 매매 알림(ADR 0028)은 지금처럼 건수·상태만이다.
   알림은 밤 결정 직후 한 통, 아침 08:00 한 통(사용자 결정).
5. **저장**: `manual_accounts`·`manual_ledger`·`manual_instructions`·`manual_sessions`(백엔드 소유, V25). 실제 계좌 자료라 저장소·문서·커밋·QA 기록에 값을 넣지 않고, 시작 장부는 배포 뒤 API로 적는다.
   S3 백업에 들어가고 QA 복원은 비운다.
6. **분리**: `feature.realtrade` 안에 두되 토스 수집기는 쓰지 않는다. ISA 자료는 모의 장부·패킷·프롬프트·복기·토스 실제 매매로 가지 않는다.

## 이유

- 연결이 없으니 시스템이 할 수 있는 정직한 일은 '무엇을 몇 주'를 정확히 알려 주고 장부를 맞추는 것이다. 계산을 토스 실제 매매와 같게 두면 두 계좌가 같은 메커니즘을 따른다.
- 사용자가 입력을 잊어도 지시가 틀어지지 않게 '지시대로 자동 기록'을 기본으로 하고, 다르게 했을 때만 고치게 했다.
- 직접 매매하려면 종목·수량이 알림에 있어야 한다. 금액은 매매에 필요하지 않아 넣지 않는다.

## 대안과 버린 이유

- **사용자가 체결을 모두 입력**: 정확하지만 입력을 빠뜨리면 다음 지시가 틀린다(사용자가 자동 기록을 고름).
- **알림은 건수만**: 휴대폰에서 바로 매매할 수 없다(사용자가 종목·수량 포함을 고름).
- **모의 책처럼 별도 모의 계좌로 둠**: 실제 돈의 장부(입출금·실제 체결가)를 담을 수 없다.

## 결과와 남은 위험

- 자동 기록은 시가 사다리 값이라 실제 체결가와 다를 수 있다 — 수수료·세금은 0으로 어림하고 사용자가 고칠 때만 들어간다.
- 1,000만 원이면 1주 단위 반올림으로 비중이 조금씩 어긋나고 현금이 일부 남는다(다음 지시가 임계값 안에서 맞춤).
- 텔레그램 서버에 ISA 지시(종목·수량)가 남는다(사용자 결정).
