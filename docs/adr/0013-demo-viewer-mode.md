# 0013. 데모 열람 — 접근 코드를 통과한 공개 방문자는 로그인 없이 읽기 전용

- 상태: 채택 (2026-10). ADR 0012의 "방문자는 데모 member 계정으로 로그인"을 대체합니다.
  읽기 전용의 예외 하나(AI 리포트 생성)는 [ADR 0014](0014-aws-demo-ai-report.md)가 더합니다.
  **v3 데모 전용** — 이 저장소(My_macro_dashboard_v1)의 AWS 배포는 [ADR 0019](0019-aws-personal-deployment.md)입니다(본문은 v3 데모 기록 그대로).
- 지키는 방법:
  - `SessionFilterTest`(데모 열람): 꺼지면 헤더 무시, 틀린 값 401, 회원·유료 GET 통과, 운영 경로 403, GET 밖(쓰기·HEAD) 403
    (`POST /api/ai/report`만 예외 — ADR 0014), 세션 우선
  - `DemoViewerTest`: 꺼짐이 기본, 32자 미만이면 기동 실패(값은 오류 문구에 없음), 정확히 같은 값만 통과
  - `AuthControllerTest`: `/api/auth/session`의 `user.demo`
  - `ApiIntegrationTest`: 데모 열람의 GET(과 AI 리포트 요청)이 사용자별 테이블에 아무것도 쓰지 않음, 쓰기 403
  - 화면: `components/shell/__tests__/Shell.test.tsx`·`MoreMenu.test.tsx`(데모 열람은 로그아웃·내 계정 없이 '데모 열람' 표시, local과 함께 와도 데모가 앞섬 —
    v2 1단계에서 옛 `Sidebar.test.tsx`의 의도를 옮김), `app/login/__tests__`, `app/(dashboard)/__tests__/demoViewer.test.tsx`

## 배경

AWS 공개 데모(ADR 0012)는 앞단 Caddy의 접근 코드 잠금화면이 방문자를 거릅니다. 그런데 잠금을 푼 방문자 앞에
앱의 이메일·비밀번호 로그인 화면이 또 나왔고, 방문자에게 공유 데모 계정의 비밀번호를 알려 줘야 했습니다.

- 접근 관리가 두 곳(접근 코드·데모 계정 비밀번호)으로 나뉩니다.
- 공유 계정은 누구나 쓰므로 그 계정으로 할 수 있는 쓰기(알림 규칙, 읽음 처리, 비밀번호 변경)가 방문자끼리 섞입니다.
  앞단에서 경로를 하나씩 막아야 했습니다.

로컬 사용은 지금처럼 로그인이 필요해야 합니다. → 2026-10-19 [ADR 0016](0016-local-no-login.md)이 대체: 로컬은 로그인 없이 이 맥에서만.

## 결정

1. **설정 `DASHBOARD_DEMO_VIEWER_TOKEN`이 있을 때만 켭니다**(기본 빈 값 = 꺼짐). 로컬 `docker-compose.yml`은 이 값을 넣지 않고,
   `compose.aws.yml`만 `.env`의 `DEMO_VIEWER_TOKEN`을 넘깁니다.
   - 32자보다 짧으면 백엔드가 기동하지 않습니다. 약한 토큰으로 조용히 켜지지 않게 하려는 것이고, 오류 문구에 값은 담지 않습니다.
2. **요청 헤더 `X-Demo-Viewer`가 그 토큰과 같으면 데모 열람 사용자로 봅니다.**
   - 세션 쿠키가 유효하면 세션이 이깁니다(운영자는 그대로 운영자).
   - 비교는 양쪽 SHA-256을 `MessageDigest.isEqual`로 합니다(걸린 시간으로 앞부분·길이를 알 수 없음).
   - 값이 틀리거나 비면 헤더가 없는 것과 같습니다(평소처럼 401).
3. **데모 열람 사용자는 계정이 없는 합성 사용자입니다** — 일반 회원(`MEMBER`)·유료 등급(`PRO`), 번호 `-1`, 이메일·세션 없음.
   - 유료 패널까지 보이고, 운영 경로는 접근 정책 표 그대로 403입니다.
   - 번호 `-1`은 실제 계정(`users.id`, 1부터)과 겹치지 않습니다. 사용자 번호를 키로 쓰는 테이블(세션·감사·사용량·알림)은
     모두 `users` FK라, 잘못 쓰면 쓰레기 행 대신 오류로 끝납니다.
4. **읽기 전용입니다.** GET·OPTIONS 밖의 `/api/*`는 경로와 상관없이 403
   `{"error":"demo_read_only","message":"데모에서는 조회만 가능합니다."}`입니다(로그인·가입 같은 공개 경로 포함).
   - 예외는 `POST /api/ai/report` 하나입니다([ADR 0014](0014-aws-demo-ai-report.md)) — 사용량은 DB 대신 방문자 전체가 함께 쓰는
     메모리의 하루 한도로 셉니다.
   - HEAD도 막습니다. 화면은 HEAD를 쓰지 않습니다. 처음에는 정책 표에 HEAD 줄이 없어 운영 GET이 실행되는 구멍(QA-017)을 피하려던 것이었고, 그 구멍은 `AccessPolicy.required`가 HEAD를 GET으로 보게 고쳤습니다(2026-10-11). 이 차단은 그 위의 한 겹으로 남깁니다.
5. **`GET /api/auth/session`은 `authenticated: true`와 `user.demo: true`를 줍니다.** 화면은 이 값으로
   - 로그아웃·내 계정 링크 대신 "데모 열람"을 보이고, `/login`·`/account`는 첫 화면(`/`)으로 보냅니다.
   - 알림 규칙·읽음 처리 버튼을 막고 "데모에서는 조회만 가능합니다"를 적습니다. ~~AI 리포트 생성 버튼도 막음~~ →
     AI 리포트는 생성 버튼을 쓰고 "데모 방문자 전체가 하루 N건을 함께 씁니다"를 적습니다(ADR 0014).

### 신뢰 모델(앞단과 나눠 지는 것)

| 누가 | 무엇을 |
|---|---|
| EC2 | 백엔드·화면 포트를 `127.0.0.1`에만 엽니다(ADR 0012). 헤더를 붙여 백엔드에 닿을 수 있는 것은 같은 호스트의 Caddy뿐입니다. |
| Caddy 공개 쪽 | 접근 코드 확인을 통과한 요청에만 `X-Demo-Viewer: <토큰>`을 **덮어써** 붙입니다(방문자가 보낸 값은 버림). GET 밖의 `/api/*`는 앞단에서도 막습니다(`POST /api/ai/report` 하나만 통과 — ADR 0014). |
| Caddy 관리자 쪽(SSM 터널) | `X-Demo-Viewer`를 **지웁니다.** 운영자는 계정으로 로그인합니다. |
| `.env` | 토큰은 서버의 `.env`(`DEMO_VIEWER_TOKEN`)와 Caddy 설정에만 둡니다. 저장소에는 이름만(`.env.aws.example`). |

토큰이 새어도 그 토큰으로 할 수 있는 것은 접근 코드를 통과한 방문자와 같습니다(읽기만, 운영 경로 403). 그래도 백엔드 포트가
루프백 밖으로 열리면 접근 코드를 건너뛰게 되므로, 포트를 여는 변경은 이 ADR을 다시 봐야 합니다.

## 이유

- **헤더(앞단이 붙임)를 고른 이유**: 접근 코드는 이미 앞단 한 곳(Caddy forward_auth)에 있습니다(ADR 0012). 앱이 접근 코드를 다시
  확인하면 두 곳이 같은 비밀을 알아야 하고, 세 프로젝트마다 따로 만들어야 합니다. 앞단이 "통과했다"는 사실만 넘기면 됩니다.
- **토큰을 두는 이유**: 헤더 이름만으로 믿으면, 앞단 설정 실수(헤더를 지우지 않음)나 루프백 안의 다른 프로세스가 곧바로 데모 열람이 됩니다.
  토큰이 있으면 실수가 401로 드러납니다.
- **합성 사용자(DB 행 없음)를 고른 이유**: 공유 데모 계정은 세션·감사 기록이 방문자마다 쌓이고, 비밀번호 변경·탈퇴 같은 쓰기를 경로마다
  막아야 했습니다. 계정이 없으면 쓸 대상 자체가 없습니다.
- **유료 등급으로 보이는 이유**: 포트폴리오 데모라 유료 패널까지 보여야 합니다. ~~유료 API를 부르는 AI 리포트 생성은 POST라 막히고,
  배포에서는 AI 키도 비어 있습니다(ADR 0012).~~ → AI 리포트 생성은 Haiku 하나·방문자 공용 하루 한도로 엽니다(ADR 0014).

## 대안과 버린 이유

- **공유 데모 계정 유지 + 화면에서 자동 로그인**: 비밀번호가 번들이나 앞단에 들어가고, 계정 쓰기를 경로마다 막는 일이 그대로 남습니다.
- **앱 안에서 접근 코드 확인**: 접근 코드가 앞단과 앱 두 곳에 있게 됩니다(ADR 0012에서 버린 "앱 안 잠금화면"과 같은 문제).
- **헤더만 보고 토큰 없이 신뢰**: 위 "토큰을 두는 이유".
- **데모 열람에 HEAD 허용**: 화면은 HEAD를 쓰지 않아 얻는 것이 없습니다. 정책 표가 HEAD를 GET으로 보게 고친 뒤(QA-017)에도 읽기 전용은 GET만으로 둡니다.

## 결과

- 새 설정: `dashboard.demo-viewer-token`(`DASHBOARD_DEMO_VIEWER_TOKEN`), 배포 `.env`의 `DEMO_VIEWER_TOKEN`.
- 새 경로 없음. `GET /api/auth/session`·`POST /api/auth/login`의 `user`에 `demo`(bool)가 더해졌습니다.
- 데모 열람의 GET이 사용자 번호로 쓰는 곳을 점검했습니다. 세션 마지막 사용 시각 갱신은 세션이 있을 때만이고, 사용량·알림 읽음·
  규칙·감사 기록은 모두 POST·DELETE이거나 정기 작업(규칙이 있는 사용자만)이라 데모 열람으로는 닿지 않습니다.
  ADR 0014 이후 데모 열람이 부를 수 있는 `POST /api/ai/report`의 사용량은 DB가 아니라 메모리에서 셉니다.
