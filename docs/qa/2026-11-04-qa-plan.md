## 3. 영역별 검증 항목과 방법

모두 **QA 스택**(§4)이나 테스트 DB에서 합니다. 운영본은 읽기 조회(머리글·TLS·출처 검사)만.

1. **장부 무결성·정기 작업**
   - 정기 작업을 겹쳐 부르기(수동 실행 경로 동시 2회), 실행 도중 백엔드 재시작(`docker compose restart` — `docker kill`은 재기동 안 됨),
     같은 관측치 재처리 → 주문·체결·현금·순자산 줄의 불변식(현금 ≥ 0, 체결 1회, 주문 상태 전이) SQL로 대조.
   - 미국·한국 초기화 → 출발 → 체결 → 확정의 상태 전이를 허용되지 않는 순서로도 호출(재출발·초기화·일시정지 사이).
   - 빈 DB에 마이그레이션 V1~V19 처음부터 적용, 다시 적용(멱등).
2. **인증·권한·출처**: `scripts/qa/auth-probe.sh`(경로 × 비로그인·회원·유료·운영자)를 v2 경로까지 넓혀 실행, 무로그인 모드(QA_NO_LOGIN)의 출처 검사,
   쿠키 속성·로그아웃 무효화·세션 만료, 로그인 시도 제한, 본문 상한(4MB), 오류 응답의 내부 정보, CORS·보안 머리글. 운영본은 같은 머리글·출처만 읽기로.
3. **입력 검증(퍼저)**: `scripts/qa/fuzz-api.py`로 모든 경로에 경계값·잘못된 형식·큰 수·음수·한글·이모지·긴 문자열 → 5xx·10초 초과·형식이 다른 오류 응답 찾기.
   v2 경로(모의 매매 설정·메모·프레임·시작·초기화 등)가 `routes.json`에 빠졌으면 먼저 넣음(계정·장부를 바꾸는 쓰기는 `fuzz:false` 유지).
4. **백업·복원·배포 되돌리기**: `make backup` → QA 스택 `restore` → 핵심 화면 값 대조. `deploy.sh`의 배포 직전 덤프로 되돌리는 절차(DEVELOPMENT §7)를
   QA 스택에서 그대로 따라 해 봄. S3 쪽은 조회만(실제 업로드·다운로드 안 함).
5. **외부 장애**: 차단 프록시의 `hang`(연결만 받고 응답 없음)·거부(403·429)·끊김으로 수집 태스크·실시간 시세·상세 → 직전 값 유지, 시간 상한, 잠금 풀림, 화면 표시.
6. **AI 경로(목)**: 프롬프트에 들어가는 외부 글(뉴스 제목·기업 개요·메모)의 구분자·지시문 주입, 하루 호출 상한·예약, 응답 스키마 위반·잘림 → 장부를 바꾸지 않음.
7. **화면(실제 브라우저)**: 모든 메뉴·탭을 360·768·1280px로 열고 버튼·폼·탭·표 조작 — 콘솔 오류, 실패·중복 요청, 가로 스크롤, 로딩·빈·오류 상태,
   새로고침·뒤로 가기·주소 직접 입력, 세션 만료. 실시간 시세 SSE는 백엔드 재시작(502) 중 재연결(QA-183)과 탭 숨김(QA-189)을 실제로.
8. **성능(QA 스택만)**: k6로 핵심 GET(개요·상태·매크로·13F·모의 매매 개요) p50·p95·p99·처리량·오류율, 동시 5·20명(단일 사용자 형태라 50명은 상한 확인만).
   백엔드 힙(4GB 서버 기준 `-Xmx`), 응답 크기, 느린 쿼리(`pg_stat_statements`를 QA 컨테이너에만 켬), 4차 리뷰가 넘긴 의심 2건(실행 감사 N+1,
   `paper_orders.decision_id` 색인)은 1년치 행을 만들어 잼. Lighthouse(성능·접근성·모범 사례).
9. **접근성**: axe-core(WCAG 2.1 A·AA)를 화면마다 주입, 핵심 흐름(메모 쓰기·설정 저장·종목 검색) 키보드만, 포커스·명도 대비.
10. **배포·운영 준비**: Vultr 덧붙임(`compose.vultr.yml`·Caddyfile)의 포트·컨테이너 사용자·무로그인 끔·HTTPS, 비밀값(.env 권한·로그·빌드 산출물·커밋 이력
    gitleaks), 헬스체크·알림, 의존성 EOL·취약점(npm audit·pip-audit·Maven 공시, 컨테이너 이미지 — 결정 3), README만 보고 새 폴더에서 빌드·실행(QA 포트로).
11. **회귀**: 전체 시험을 세 번 돌려 흔들리는 시험 표시, 중요한데 시험이 없는 경로 목록.

2. **QA 데이터**: (로컬 스택 백업 사본을 QA 스택에 복원 — 운영 덤프는 쓰지 않음)
3. **작업 환경 전용 도구 설치**: Playwright(npm, 임시 폴더)·k6·trivy(docker 이미지)·Lighthouse(npx) (설치함 — 프로젝트 의존성 변경 없음)
4. **운영본 읽기 조회**: 보안 머리글·TLS·출처 검사만 tailnet에서 읽기 (함 — 부하·쓰기 없음)
5. **화면 폭·성능 목표**: (360·768·1280px, 성능 목표 없음 → 측정값을 기준선으로)
6. **수정 배포**: (묶음마다 `main` → CI → Vultr 배포, Tailscale 인증이 필요하면 그때 여쭘)
