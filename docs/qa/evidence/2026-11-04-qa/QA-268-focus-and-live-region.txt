# 출처: $SP/qa/lanes/repro12/SUMMARY.txt (전체)
repro12 — 후보 "메모 저장·알림 규칙 만들기 뒤 초점 소실·결과 배너 라이브 영역 아님" 독립 재현 (커밋 49a7d62b 코드, QA 스택 13002/18082)
- focus-repro.js / focus-repro.out.json : 실제 POST(메모 #4 → 끝에 DELETE로 보관, 알림 규칙 #3 → 끝에 DELETE). Enter 직후 초점=disabled 단추('저장 중…'/'만드는 중…'), 150ms 뒤 body.
  메모: 성공 뒤 단추 계속 disabled(입력 비움). 알림: 단추는 다시 enabled지만 초점은 body. 두 배너 모두 조상에 role=status/alert/aria-live 없음.
  페이지의 라이브 영역은 RefreshButton의 빈 <p role=status class=sr-only> 하나.
- focus-order.js / focus-order.out.json : 쓰기 없음(알림 POST는 가짜 응답). 초점 소실 뒤 Shift+Tab → 바로 앞 select(탭 순서 index 24/26) — Chrome은 순차 초점 시작점을 단추 자리에 유지.
  Tab → 단추가 마지막 요소라 문서 밖(body) → 다음 Tab에 '본문으로 건너뛰기'. 메모 화면도 다음 Tab이 단추 뒤의 '맨 위로'.
  => 후보의 "다음 Tab은 문서 처음부터"는 Chrome에서 사실 아님(키보드 영향 작음). 낭독기 미알림(4.1.3)은 DOM으로 확인, 실제 낭독기는 안 돌림.
- jsdom-disable.cjs : jsdom 29.1.1은 초점 단추를 disabled로 만들어도 activeElement가 단추 그대로 — vitest로 'body로 빠짐'은 재현 안 됨, role=status 단언이 확실.
- 정리 확인: paper_notes #4 archived=t, alerts rules = [1]만.
