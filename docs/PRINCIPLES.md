# 이 프로젝트가 지키는 규칙

이 문서는 **왜 이렇게 만들었는지**를 모아 둔 곳입니다. 대부분은 실제로 한 번씩
틀렸던 경험에서 나온 규칙이고, 각 항목에 그 사고가 함께 적혀 있습니다.

새 기능을 붙이기 전에 관련 항목을 읽으세요. 여기 적힌 규칙은 테스트로도 고정되어
있어서, 어기면 빌드가 깨집니다.

> 시작하는 방법은 [README](../README.md), API 목록은 [API.md](API.md),
> 구조는 [ARCHITECTURE.md](ARCHITECTURE.md)를 보세요.

---

금융 데이터가 "조용히 틀리는" 사고를 막기 위한 규칙들입니다. 모두 **코드와
테스트로** 강제합니다.

## 수집 실패 시 숫자를 만들어내지 않습니다

- 실패는 `status="fail"`, 빈 결과, `available=false`로 드러납니다.
- 화면은 값이 없으면 `—`로 표시합니다. **0.00%로 채우지 않습니다** —
  "0.00%"는 '데이터 없음'이 아니라 '보합'으로 읽히기 때문입니다.
- 전일 종가를 모르면 "전일 대비 미제공"입니다. 현재가를 전일값처럼 쓰지 않습니다.

## 차트는 축부터 정직해야 합니다

면적 차트의 Y축을 늘 0부터 그리면, 0 근처에서 움직이지 않는 계열은 변동이
사라집니다. 순유동성(5.85~6.0조 달러)에 0~8조 축을 쓰면 읽어야 할 움직임이
축 꼭대기 얇은 띠에 눌려 직선처럼 보였습니다. 0이 의미를 갖는 계열(스프레드
처럼 부호가 중요한 값)만 0을 포함시키고, 나머지는 데이터 범위에 맞춥니다.
반대로 값이 음수가 될 수 없는 계열(역레포 등)은 축을 0 아래로 내리지
않습니다 — 있을 수 없는 값을 있을 수 있는 것처럼 보여 주게 됩니다.

**자릿수가 다른 계열을 한 축에 겹치지 않습니다.** 총자산 6.7조 · 재무부 계정
0.88조 · 역레포 0.005조를 한 축에 그리면 아래 둘이 바닥에 눌려 직선이 됩니다.
축을 둘로 나누는 것(이중 축)은 두 축의 정렬이 임의라 **없는 상관을 만들어
냅니다.** 그래서 패널을 나눕니다 — 각자 제 범위를 갖고 시간축만 공유합니다.

**같은 화면의 숫자 타일과 차트는 같은 단위를 씁니다.** 패널을 나눠 놓고도
타일은 "5.2 십억 달러", 차트 눈금은 "0.01T"로 적으면 읽는 사람이 머릿속에서
단위를 환산해야 합니다. 게다가 역레포 실제 수준(약 0.005조)에서는 소수 두
자리 눈금이 전부 `0.00T`이 되어, 패널을 나눈 목적이 그대로 사라집니다.
총자산은 조 달러(T), TGA·RRP는 십억 달러(B)로 각 패널 제목 옆에 단위를 적습니다.

**선 하나로 판정까지 전하지 않습니다.** 0선은 "0이 여기"까지만 말합니다.
"지금 역전 상태"라는 판정은 차트 위 배너 한 줄이 글로 적습니다(색·선만으로
의미를 전달하지 않기 위해서입니다). 금리차 카드와 심화 매크로의
T10Y3M·NFCI가 그렇습니다.

**기간 선택은 저장된 구간을 넘지 않습니다.** 수집기는 FRED에서 10년 + 90일을
받아 둡니다(`period_years=10`). 그래서 기간 탭은 1·3·5·10년까지만 둡니다.
"전체" 탭을 만들면 10년과 똑같은 그림이 나오면서, 읽는 사람은 1982년부터의
T10Y3M을 보고 있다고 오해합니다. 더 긴 구간이 필요하면 탭이 아니라 **수집
구간**부터 늘려야 합니다.

계열 색은 눈대중으로 고르지 않고 검증기(dataviz `validate_palette.js`)를
돌립니다. 이전 조합은 적록색약에서 노랑↔빨강 ΔE가 5.8로 구분 한계(6) 아래라,
두 선이 실제로 겹쳐 보였습니다. v2 1단계(2026-10-26)에 라이트·다크 두 바탕에서 계열 팔레트를
다시 돌렸고, 결과와 바꾼 값은 [UI 설계 §11-2](specs/2026-10-26-v2-ui-design.md)에 있습니다.

## 추정치는 추정치라고 말합니다

| 값 | 표시 |
|---|---|
| KRX 수집 실패 시 KODEX 200 기반 선물 가격 | `isEstimated=true` + 화면 경고 배너 |
| MOVE 지수 (Yahoo가 제공하지 않음) | `isProxy=true` + "실제 ICE BofA MOVE 아님" |

추정치는 **누적 이력 테이블에 쓰지 않습니다.** 한 번 섞이면 실제 확정치와
구분할 수 없습니다.

## 모르면 "판정 불가"입니다

KOSPI200 선물 4대 국면은 등락률과 미결제약정 증감이 모두 있어야 판정합니다.
결측을 0.0으로 메우면 `등락률 >= 0`이 항상 참이 되어, **하락한 날에도 '신규
롱'(강세)** 으로 판정됩니다(예: 2026-09-11 실제 −2.13%). 그래서 등락률은 연속된
확정 종가에서 직접 계산하고, KRX 보고값은 대조용으로만 남깁니다.

## "확인 못 함"과 "일치"를 섞지 않습니다

교차 검증 판정은 네 가지입니다: **일치 / 불일치 / 수집 실패 / 확인 못 함**.
키가 없어 비교하지 못한 것을 "일치"로 표시하면 검증 자체가 거짓말이 됩니다.

시간 조건이 항목마다 반대인 것도 그대로입니다 — KRX는 *일별 확정 종가*, KIS는
*현재가*를 주므로 시세 대조는 **장 마감 후**에만, KIS 수급 가집계 TR은 장중
전용이라 수급 대조는 **정규장 중**에만 가능합니다.

토스 키가 없으면 토스 항목(코스피 종합지수·원/달러·수급 정합성)도 "확인 못 함"입니다.
토스 수급 정합성은 당일 잠정치(빈 값)를 0으로 메워 등식을 "통과"시키지 않고,
값이 모두 채워진 가장 최근 확정 기록만 봅니다.

**기준일이 다르면 비교하지 않습니다.** 시간대가 맞아도 KRX 확정치는 하루 이상
늦게 올라오는 반면 KIS는 최신값을 줍니다. 이때 그냥 비교하면 "불일치"가 뜨는데,
값이 갈라진 게 아니라 **서로 다른 날을 본 것**입니다. 읽기값마다 기준 거래일을
달고, 날짜가 어긋나면 "확인 못 함"으로 둡니다. 이 검사가 없으면 KRX가 밀리는
날마다 거짓 경보가 울리고 그 사이 진짜 불일치가 묻힙니다.

## 화면은 수집을 기다리지 않습니다

읽기 모드(`DASHBOARD_READ_MODE`)로 동작을 고릅니다.

| 값 | 동작 |
|---|---|
| `auto` (기본) | 저장본이 신선하면 사용, 오래되면 수집기에 수집 요청 |
| `store_only` | 저장본만 사용. 오래돼도 그대로 보여주고 외부를 **절대** 기다리지 않음 |
| `live_only` | 신선해도 읽을 때마다 수집 요청(비동기, 30초 쿨다운). 저장본이 있으면 그대로 보여 줌 (디버깅용) |

**저장본이 있으면 절대 기다리지 않습니다.** 오래된 저장본을 발견하면 수집을
요청만 해 두고(비동기) 화면에는 기존 값을 즉시 보여 줍니다. 각 메뉴 오른쪽 위의
신선도 배지가 **수집한 시각**(`🕒 수집 2026-09-25 20:55`)을
그대로 말해 주고, 수집이 끝나면 다음 조회에서 새 값이 나옵니다. 수집이 끝날 때까지
붙잡으면 `sec_13f` 31.8초 · `fred_series` 11.5초가 그대로 화면 대기 시간이 됩니다.
보여 줄 값이 아예 없을 때만 기다립니다 — 빈 화면보다는 낫기 때문입니다.

같은 태스크 재요청은 30초 동안 억제합니다. 화면 하나가 스냅샷을 병렬로 읽으면
같은 요청이 그만큼 나가는데(실제로 한 번의 페이지 로드에 `fred_series` 요청이
7건이었습니다), 수집기가 합쳐 주기는 해도 애초에 보내지 않는 편이 낫습니다.

**수동 새로고침도 분기 공시까지 다시 받지는 않습니다.** 새로고침은 "이 시각
이전 저장본은 낡은 것으로 본다"는 기준을 세우는데, 그 기준이 데이터셋 종류를
가리지 않으면 버튼 한 번에 13F 전수 수집이 다시 돕니다(실제로 5분 사이에 SEC
수집이 세 번 돌았습니다). SEC·FRED는 호출 한도를 명시하고 초과하면 차단합니다.
데이터셋 종류별로 최소 재수집 간격을 둡니다 — 시세성 1분, 일별 확정치 30분,
분기 공시 6시간. 빠르게 바뀌는 데이터는 거의 제한하지 않습니다(새로고침을
누르는 이유가 대개 그쪽입니다).

수동 새로고침은 저장본을 **지우지 않습니다.** "이 시각 이전 저장본은 낡은
것으로 본다"는 기준만 세웁니다 — 수집이 실패하면 보여 줄 값이 아예 없어지기
때문입니다.

버튼을 누르면 수집을 요청하고 **끝날 때까지 기다렸다가 화면이 스스로
갱신됩니다.** 기다리는 동안 버튼은 `수집 중… 끝나면 자동 갱신`으로 바뀝니다.
수집은 백그라운드로 돌기 때문에, 요청 직후에 다시 읽으면 아직 이전 값입니다.
수집기가 새 실행 번호를 남기고 끝났는지를 보고 갱신 시점을 정합니다.

## 로그에 비밀값을 남기지 않습니다

API 키가 로그로 새어 나간 적이 있습니다. FRED 호출이 느려 urllib3가 재시도
경고를 찍었는데, 그 경고에 **요청 URL 전체**가 들어 있었습니다.

```
WARNING urllib3.connectionpool: Retrying (...) after connection broken by
'ReadTimeoutError(...)': /fred/series/observations?series_id=WALCL
&api_key=deadbeefdeadbeefdeadbeefdeadbeef&file_type=json&...
```

URL을 찍는 쪽이 서드파티 라이브러리라 우리 코드만 조심해서는 막을 수
없습니다. **로깅 계층에서** 가립니다(`collector/app/logredact.py`) — 어떤
코드가 찍든 출력 직전에 한 곳에서 걸립니다. `api_key`·`auth_key`·`appkey`·
`app_secret`·`access_token`·`password`와 `Bearer` 토큰이 대상입니다.
진단에 필요한 나머지(`series_id=WALCL` 등)는 그대로 남깁니다.

> 위 예시의 키 값은 **실제 키가 아닌 자리 표시자**(`deadbeef…`)입니다.
> 문서·테스트·주석에는 진짜 키를 적지 않습니다. 한 번 커밋되면 나중에 지워도
> 커밋 이력에 그대로 남기 때문입니다.

**이미 새어 나갔다면 가리는 것으로는 부족합니다 — 재발급하세요.** 로그·터미널
기록·스크린샷·커밋 이력 어디에든 한 번 찍혔다면 그 키는 더 이상 비밀이
아닙니다. 발급처에서 새 키를 받고, `.env`의 값을 바꾼 뒤 `make up`으로 컨테이너를
다시 올리면 됩니다(코드 수정은 필요 없습니다).

| 키 | 재발급 위치 |
|---|---|
| `FRED_API_KEY` | <https://fredaccount.stlouisfed.org/apikeys> |
| `KRX_API_KEY` | KRX OPEN API 마이페이지 |
| `KIS_APP_KEY` / `KIS_APP_SECRET` | 한국투자증권 KIS Developers |
| `LS_APP_KEY` / `LS_APP_SECRET` | LS증권 OPEN API |

## 한 출처에는 한 가지 방법으로만 붙습니다

같은 출처에 두 가지 방식으로 붙으면 한쪽만 조용히 막히고, 화면에는 설명할 수
없는 상태가 남습니다. 실제로 그랬습니다 — 같은 시각 같은 종목인데 매크로
카드(yfinance)는 `WTI 102.47`, 스크래핑 비교표(생 requests)는
`429 Too Many Requests` 였습니다. 데이터가 아니라 **클라이언트**가 달랐던
것입니다. yfinance는 Yahoo가 요구하는 쿠키·crumb를 관리하지만 생 호출은
그 처리가 없어 먼저 차단됩니다.

Yahoo로 가는 길은 `services/market.py` 하나로 모읍니다. 테스트가 `query1…`
직접 호출이 다시 들어오는 것을 막습니다.

## 같은 수집을 동시에 두 번 돌리지 않습니다

화면 하나를 여는 것만으로 같은 태스크가 여러 번 돌 수 있습니다. 백엔드는
스냅샷을 읽다가 오래됐으면 수집을 요청하는데, 한 화면이 여러 스냅샷을 병렬로
읽으면 그 요청이 각각 나가기 때문입니다. 실제 로그에서 `cot_history`가 같은
초에 네 번, `fred_series`가 세 번 동시에 돌았습니다. 외부 API 호출이 그대로
몇 배가 되고(FRED·SEC는 호출 한도가 있습니다) 같은 행을 동시에 쓰게 됩니다.

수집기는 이미 도는 태스크가 있으면 **새로 시작하지 않고 그 결과를 기다렸다가
함께 씁니다.** 뒤늦게 온 호출을 거절하지 않는 이유는, 호출자가 원하는 것이
"지금 새로 받아라"가 아니라 "신선한 값을 달라"이기 때문입니다.

## 금액은 한국식 단위(조·억)로 통일합니다

달러 금액을 `$299.25B`처럼 적으면, 한국어로 읽을 때 자릿수를 머리로 한 번 더
옮겨야 합니다. 이 대시보드는 원화 금액과 나란히 읽는 화면이 많아 **두 통화를
같은 단위 체계**로 맞춥니다.

| 전 | 후 |
|---|---|
| `877.0 십억 달러` | `8,770억 달러` |
| `0.012 조 달러` | `120억 달러` |
| `$299.25B` | `2,992.5억 달러` |
| (없음) | `2,992.5억 달러 (약 413.4조 원)` |

1,000조가 넘으면 소수를 떼고 정수로 적습니다. `8,607.639조 원`에서 뒤 세 자리는
6,390억인데, 8,607조 옆에 붙어 있으면 자릿수만 다시 세게 만듭니다.

원화 환산은 **매크로 화면이 이미 수집한 원/달러**(`/api/macro/usdkrw`)를 그대로
씁니다. 화면마다 따로 받아 오면 같은 포트폴리오가 메뉴에 따라 다른 원화 금액으로
보입니다. 화면 쪽은 훅 하나(`useUsdKrw`)로 모여 있어 갈라질 수 없습니다.
**환율을 모르면 원화를 적지 않습니다** — 기본 환율(예: 1,300원)로 지어내면
틀린 금액을 사실처럼 보여 주게 됩니다. 환산 함수가 값 대신 `null`을 돌려주고,
화면은 그 줄을 통째로 생략합니다.

원화를 병기하는 화면: 🏢 연준 순유동성(순유동성·총자산·TGA·RRP·4주/12주 변화),
📑 기관 13F 포트폴리오(총액 + 종목별 평가액), 🎯 13F 교집합(합산 평가액).

## 단위가 다른 계열을 겹칠 때는 기준일을 100으로 맞춥니다

원/달러(약 1,380)·달러/엔(약 150)·엔/원(약 930)·달러 인덱스(약 100)를 원래 단위로
한 축에 겹치면 축이 0~1,400이 되고, 아래 둘은 바닥에 눌려 **직선**이 됩니다.
그래서 💱 환율 비교 차트의 기본은 **기준일 = 100**입니다 — 각 계열을 창의 첫 값으로
나눠 100에 맞추면, 축이 "기준일 대비 %"가 되어 무엇이 더 많이 움직였는지 비교할
수 있습니다.

원래 단위도 고를 수 있습니다. 막지 않는 이유는 사용자가 고른 것이기 때문이고,
대신 단위가 섞이면 **무슨 일이 일어나는지 화면이 먼저 말해 줍니다**(경고 배너).

두 가지를 더 지킵니다.

- **기준값은 계열마다 각자의 첫 유효값**입니다. 공통 시작일을 강제하면 거래일이
  하루 다른 계열이 통째로 빠집니다(환율은 시장마다 휴일이 다릅니다). 대신 계열별
  기준일을 카드에 적습니다.
- **날짜는 교집합이 아니라 합집합**입니다. 한 계열이 쉰 날의 다른 계열 값을 버리지
  않고, 값이 없는 날은 비워 둡니다 — 없는 거래를 선으로 이으면 실제로는 없던
  흐름이 생깁니다.

차트의 티커는 **매크로 카드와 같은 것**을 씁니다(수집기 `fx_history`). 차트만
다른 티커를 쓰면 카드의 최근값과 차트의 끝값이 어긋나고, 보는 사람은 둘 중 무엇이
맞는지 알 수 없습니다. 엔/원의 100엔당 환산 판정도 카드와 같은 함수
(`market.quote_scale`)를 씁니다.

## 분석은 근거와 한계를 함께 보여 줍니다

국면 판정·상관관계·COT 백테스트는 결론만 내놓지 않습니다.

| 화면 | 함께 보여 주는 것 | 왜 |
|---|---|---|
| 🧭 시장 국면 | 판정에 쓰인 지표 4개의 값·상태·해석 | 결론에 동의하지 않아도 근거는 확인할 수 있어야 합니다 |
| 🧭 시장 국면 | 입력이 하나라도 없으면 **판정 불가** | 빠진 값을 0으로 메우면 "중립"이라는 틀린 판정이 됩니다 |
| 🔗 상관관계 | 표본 수 · "상관은 인과가 아닙니다" · 수준 비교 시 허위 상관 경고 | 0.9라는 숫자는 두 계열이 추세만 가져도 나옵니다 |
| 📉 COT 백테스트 | **아무 때나 들어갔을 때**의 성적을 나란히 | 비교 기준이 없으면 좋은 숫자인지 알 수 없습니다 |
| 📉 COT 백테스트 | 백분위를 **그 시점까지의 과거**로만 계산 | 전체 표본으로 재면 그때는 알 수 없던 사실로 과거를 판정하게 됩니다 |
| 📉 COT 백테스트 | 가격이 **ETF 대용**이라는 표시 | COT 공시에는 가격이 없습니다. 선물 수익률로 오해하면 안 됩니다 |
| 📉 COT 백테스트 | 수익률은 **공시(금) 다음 거래일**부터 | 기준일(화) 종가에서 재면 공시 전 사흘을 신호의 성과로 셉니다(QA-012) |
| 📈 국면 판정 성과 | 그날까지 **발표된** 값으로만 재현(NFCI는 다음 주 수요일) | 관측일로 재현하면 아직 나오지 않은 값으로 판정합니다 |
| 📈 국면 판정 성과 | 표본 부족(20건 미만·독립 3개 미만)이면 **숫자 대신 "표본 부족"** | 몇 개뿐인 평균은 우연인데 숫자가 보이면 신호로 읽힙니다 |
| 📒 판정 기록 | 하루 한 건, **추가만** | 성과를 공개할 때 "나중에 맞춰 고친 판정이 아니다"를 보증합니다 |
| 🤝 외국인·기관 공통 수급 | **"상위 N 목록의 교집합"**이라는 문구 | 소스(Daum)가 상위 목록만 줍니다. 상위 N 밖에서 같은 방향으로 매매한 종목은 알 수 없습니다 |
| 🛡️ 구루 포트폴리오 위험 | **커버리지를 결과보다 먼저** | 13F에는 티커가 없어 이름으로 가격을 찾습니다. 덮인 것만으로 낸 값을 전체인 것처럼 보여 주면 안 됩니다 |
| 🛡️ 구루 포트폴리오 위험 | 비중을 **매일 재조정한다는 가정** | 13F는 분기에 한 번 찍힌 사진입니다. 그사이 실제 비중은 알 수 없으므로, 가정을 두고 그 가정을 적습니다 |
| 🩺 종목 스코어카드 | **"종합 점수가 아닙니다"**와 빠진 항목 목록 | 재무·성장·밸류에이션이 없습니다. 부실기업도 주가만 오르면 높은 점수를 받습니다 |
| 🩺 종목 스코어카드 | 백분위의 **비교 대상과 표본 수** | "70점"은 무엇 대비 70점인지 모르면 아무 뜻이 없습니다. 비교 대상이 10개 미만이면 점수를 내지 않습니다 |
| 🤝 외국인·기관 공통 수급 | 한쪽 금액이 없으면 **합계를 만들지 않음** | 0으로 채우면 "기관은 안 샀다"가 아니라 "기관이 0억 샀다"로 읽힙니다 |
| 💱 환율 비교 | 계열별 **기준일**과 축의 의미 | 기준일이 다르면 같은 110%가 다른 기간의 값입니다 |

## 13F에는 종목코드가 없습니다

SEC 13F 공시가 주는 것은 이게 전부입니다.

```json
{"name": "MICROSOFT CORP", "class": "COM", "cusip": "485151262",
 "value": 7140353471, "shares": 14383409, "weight": 17.157}
```

가격을 받으려면 티커가 있어야 하는데, SEC는 CUSIP↔티커 매핑을 무료로 주지
않습니다(상용 라이선스 데이터입니다). 그래서 대형주 이름을 직접 적어 둡니다 —
`collector/app/equities.py`.

이 방식은 **덮지 못하는 종목이 반드시 생깁니다.** 버크셔처럼 대형주에 집중한
포트폴리오는 비중의 대부분이 덮이지만, 노르웨이 국부펀드처럼 수천 종목을 든
기관은 커버리지가 낮게 나옵니다. 그래서 화면은 **커버리지를 결과보다 먼저**
보여 주고, 미커버 종목을 이름과 비중까지 펼쳐 볼 수 있게 합니다.

이름이 비슷하다고 아무 티커나 붙이지 않습니다. 두 단계(정확히 일치 → 법인격
표기 제거 후 일치) 모두 실패하면 "모른다"로 둡니다 — 엉뚱한 회사의 가격으로
위험을 계산하는 것보다 빠지는 편이 낫습니다. 같은 이유로 펀드·ETF·신탁은 법인격을 떼어도 운영회사에 붙이지
않고, 채권(PRN)·노트·전환사채 행은 주가로 덮지 않습니다. 우선주(의무전환 우선주 포함)·워런트·지분 유닛도 같은
회사 보통주의 가격으로 대신하지 않고 미커버로 둡니다 — 영구 우선주는 채권처럼, 워런트는 레버리지로 움직여
보통주 가격과 다릅니다(QA-127). 미커버 목록은 이렇게 일부러 뺀 행에 '매핑표에 없음' 대신 그 이유를 적습니다.
이 매칭은 수집기 한 곳(`equities.py`)에서 13F를 저장할 때 하고, 백엔드는 붙은 티커와 이유를 읽기만 합니다.

## 위험 기여의 합은 포트폴리오 변동성과 같습니다

종목별 위험 기여도는 개별 변동성을 비중으로 가중해 더한 값이 **아닙니다**.
그렇게 하면 분산 효과가 사라져 합이 포트폴리오 변동성보다 커집니다.

한계기여 = cov(종목, 포트폴리오) ÷ 포트폴리오 표준편차, 기여 = 비중 × 한계기여.
이렇게 하면 **기여의 합이 포트폴리오 변동성과 정확히 일치**합니다(테스트가
이 항등식을 고정합니다).

이 표를 두는 이유는 하나입니다 — **비중이 큰 종목이 곧 위험이 큰 종목은
아닙니다.** 조용한 대형주 20%와 널뛰는 종목 5%의 기여가 뒤집히는 일이 흔합니다.

## 과거 조회가 안 되는 소스는 우리가 이력을 쌓습니다

Naver·Daum·KIS는 "가장 최근에 끝난 거래일"만 줍니다. 수집기가 돌 때마다 그날의
수급 랭킹을 `observations`에 적재하고, 외부 소스가 모두 실패하면 그 이력으로
대체합니다. 이때 화면에는 **어느 날짜의 저장본인지**와 "지금 시점의 수급이
아니다"라는 경고가 반드시 함께 뜹니다.

> **수집기를 꾸준히 돌리는 것이 곧 백업입니다.** PostgreSQL 볼륨은 백업할
> 가치가 있습니다.

## 로그인이 없는 경로는 이 맥 밖으로 열지 않습니다

로컬(기본 `LOCAL_NO_LOGIN`)에서는 **컨테이너 네 개 모두 로그인 없이 열립니다** — 화면·API는 로그인 없이 운영자로(ADR 0016),
PostgreSQL·수집기는 비밀번호가 없거나(`macro/macro`) 내부 토큰 하나로만 막혀 있습니다. 그래서 네 포트를 모두 이 맥에만 엽니다.
밖으로 열면 같은 와이파이에 있는 누구나 운영자가 되거나 DB에 붙거나 수집기 API로 데이터를 받아갈 수 있습니다(카페·공용
와이파이에서는 그대로 노출). 로그인은 `LOCAL_NO_LOGIN=false`·QA 스택·웹(AWS)에서만 요구합니다.

| 서비스 | 포트 | 어디까지 열리나 | 이유 |
|---|---|---|---|
| frontend | 3000 | `127.0.0.1` | 로컬은 로그인 없이 운영자로 열려 이 맥에서만 엽니다(ADR 0016) |
| backend | 8080 | `127.0.0.1` | 로그인 없는 요청은 이 맥의 이름(localhost 등)·이 맥 화면의 출처에서 온 것만 운영자로 받습니다 |
| collector | 8000 | **127.0.0.1 고정** | 호출 한 번이 외부 수집·저장을 일으킵니다 |
| postgres | 5432 | **127.0.0.1 고정** | 기본 계정이 `macro/macro`입니다 |

컨테이너끼리는 Docker 내부 네트워크로 통신하므로 **기능 손실이 없습니다.**
`make db`·`make status`·`make doctor`도 `127.0.0.1`로 붙으므로 그대로 동작합니다.

로컬은 로그인 없이 운영자로 열리므로(ADR 0016) 다른 기기에 여는 방법은 두지 않습니다 — AWS 개인용 서버도 PC의 SSM 터널로만
엽니다(ADR 0019, 휴대폰 접속 없음). 운영자 계정의 비밀번호는 로그인 모드·QA 스택·이 DB를 복원한 곳에서 대시보드 전체의 접근 통제이므로 누구나 아는 값은
받지 않습니다 — 처음 운영자 계정은 `APP_PASSWORD`가 비었거나 공개된 기본값(`admin1234@`)이면 만들지 않고, `make setup`은
이 두 경우 무작위 비밀번호를 만들어 줍니다. 새 비밀번호는 10자 이상·흔한 값 금지 규칙을 따릅니다.

수집기 API에 토큰(`COLLECTOR_API_TOKEN`, `make setup`이 채움)을 설정하면 수집을
유발하는 경로가 전부 막힙니다. `/health`와 `/status`만 열어 둡니다 — 컨테이너
헬스체크와 `make status`·`make doctor`가 쓰고, 비밀값은 담지 않습니다(키는 설정
여부만 `true/false`로 알립니다). 토큰이 비어 있으면 수집기는 기동하지 않습니다.
`COLLECTOR_ALLOW_NO_TOKEN=1`을 명시했을 때만 인증 없이 요청을 받고, 그 사실을 기동할 때 경고 로그로 남깁니다.

`127.0.0.1`에만 열어도 **이 맥의 브라우저**는 수집기에 닿습니다. 대시보드를 켜 둔 채
방문한 다른 사이트가 (지금은 없앤) `/maintenance/purge`를 부르면 다시 받을 수 없는
누적 이력이 지워졌습니다(재현: 100행 → 0행). `/collect`처럼 수집을 일으키는 경로도
같은 식으로 불립니다. 그래서 브라우저가 보낸 다른 출처의 요청은 토큰과 상관없이
403으로 막습니다(`Sec-Fetch-Site`·`Origin` 검사, `collector/app/webguard.py`).

## 자동 갱신은 지킬 수 있는 주기만 약속합니다

매크로 화면은 갱신 간격을 고를 수 있습니다(10초·30초·1분·5분·10분·30분·끄기).
고르면 **페이지를 새로 그리지 않고 숫자만** 바뀌고, 선택은 브라우저에 기억됩니다.

**목록에 '실시간'은 없습니다.** 매크로 카드 21개는 Yahoo와 TradingView 공개 시세를
폴링해서 받아옵니다(한 번에 약 3초). 카드마다 출처의 지연이 달라(Yahoo는 0~20분, 원자재·
지수 선물은 10분) 카드 배지에 적고, 같은 종목의 실시간 공개 시세가 있으면 그것을 먼저 씁니다
([ADR 0017](adr/0017-macro-card-delay-and-realtime-sources.md)). '실시간' 배지도 폴링이라
화면의 값은 마지막 수집 시각의 것입니다. WebSocket 스트리밍을 주는 소스는 KIS(국내 주식
체결가)뿐이라 환율·미국채·원자재에는 쓸 수 없습니다. 초 단위 실시간은 구현의 문제가 아니라
데이터의 문제라, 지킬 수 없는 선택지를 목록에 넣지 않았습니다.

**값이 실제로 움직이는 하한은 60초입니다.** 10초를 골라도 저장본 기준이 15분이면
같은 숫자만 다시 그립니다. 그래서 1분 이하를 고르면 화면이 `?live=true`로 요청하고,
백엔드가 저장본 기준을 60초로 낮춰 그만큼 자주 수집을 맡깁니다. 더 낮추지 않는
이유는 **Yahoo 429**입니다 — 이 저장소는 차단으로 매크로 화면이 빈 이력이 있습니다.

| 고른 간격 | 화면이 다시 읽는 주기 | 값이 바뀌는 주기 | 매크로 외부 요청(시간당) |
|---|---|---|---|
| 끄기 | 없음 | 수집기 스케줄 5분 | 약 252건 |
| 10초·30초·1분 | 고른 대로 | 최대 1분 | 약 1,260건 |
| 5분·10분·30분 | 고른 대로 | 수집기 스케줄 5분 | 약 252건 |

리스크·심화 지표는 일별·주별 확정치라 기존 주기(2분·5분)보다 빨라지지 않습니다.
탭을 다른 곳으로 옮기면 자동 갱신이 멈추고, 돌아오면 즉시 한 번 읽습니다 —
아무도 보지 않는 화면이 수집기를 깨우지 않게 하기 위해서입니다.

'⚠️ 오래된 저장본' 배지는 갱신 간격과 무관하게 **15분** 기준을 그대로 씁니다.
배지가 데이터 품질이 아니라 화면 설정을 말하게 되면 안 되기 때문입니다.

이 선택이 지켜지는지는 `MacroLiveModeTest`가 고정합니다 — 60초 하한을 누군가
낮추면 테스트가 먼저 깨집니다.

## 알림은 확정된 사실만, 한 번만 알립니다

알림은 잘못 울리면 다음 알림부터 믿지 않게 됩니다. 그래서 알림 사건은 다음 규칙으로만 만듭니다(ADR 0011).

| 규칙 | 왜 |
|---|---|
| 잠정치·추정치·오래된 저장본으로는 만들지 않음(오늘 투자자 매매 기록 제외) | 장중 잠정치는 저녁에 바뀝니다. 바뀐 값으로 이미 울린 알림은 되돌릴 수 없습니다 |
| 국면 전환은 새 판정이 기록에서 3일 이어질 때 | 3년 재현에서 국면이 약 58번 바뀌었습니다. 하루 이틀 바뀌었다 돌아오는 것을 전환으로 알리면 소음입니다 |
| 같은 사건은 한 번(사건 키·알림함 유일 제약) | 평가가 몇 번 돌아도 결과가 같아야 합니다 |
| 규칙을 만든 날보다 앞선 사건은 보내지 않음 | 처음 켤 때 과거 사건이 쏟아지면 무엇이 지금 일인지 알 수 없습니다 |
| 근거·기준일·출처 성격·한계를 담고 행동 지시는 쓰지 않음 | 알림은 "이런 일이 있었다"까지입니다. 금지어는 테스트가 막습니다 |

## 공휴일과 거래소 휴장일을 섞지 않습니다

화면 위쪽 시계는 "거래 중 / 장 마감 / 휴장"을 표시합니다. 휴장은 **공휴일 목록**으로
판정하면 틀립니다. 두 가지는 다릅니다.

| 날 | 공휴일인가 | 증시가 열리나 | 공휴일 목록으로 판정하면 |
|---|---|---|---|
| 컬럼버스데이 | ✅ 연방 공휴일 | ✅ **열립니다** (채권만 휴장) | ❌ "휴장"이라고 거짓말 |
| 재향군인의 날 | ✅ 연방 공휴일 | ✅ **열립니다** | ❌ "휴장"이라고 거짓말 |
| 성금요일 | ❌ 공휴일 아님 | ❌ **닫습니다** | ❌ "거래 중"이라고 거짓말 |

또 브라우저가 외부 공휴일 API를 직접 부르면 "화면이 쓰는 데이터는 모두 우리 백엔드를
거친다"는 원칙이 깨지고, 인터넷이 막히면 조용히 주말 판정만 남습니다.

그래서 `frontend/src/lib/marketCalendar.ts`가 계산합니다.

- **미국** — NYSE·NASDAQ 휴장 규칙은 날짜 규칙이라 계산할 수 있습니다
  (1월 셋째 월요일, 부활절 이틀 전, 토요일이면 전날 금요일 …). 해가 바뀌어도
  손댈 필요가 없고, `marketCalendar.check.mts`가 2024~2027년을 검증합니다.
- **한국** — 설날·추석·부처님오신날은 음력이라 계산할 수 없어 표로 둡니다.
  **표에 없는 해는 양력 휴일만 반영하고, 배지에 "설날·추석 휴장일이 표에
  없습니다"를 함께 띄웁니다.** 모르는 것을 아는 척하지 않습니다.

### 지표 카드의 개장/마감 배지

매크로 화면의 카드마다 "개장 · 휴식 · 마감 · 휴장 · 휴장 추정"을 붙입니다.
`frontend/src/lib/marketSessions.ts`가 거래소별 시간표(출처는 파일 머리말)로
**보는 시각 기준**으로 판정합니다. 수집 시점에 계산해 저장하지 않는 이유는, 저장한
순간부터 틀린 값이 되기 때문입니다. 수집기는 지표마다 시장 id(`market`)만 붙입니다.

- **휴장일 목록이 있는 시장** — KRX(천문연 공식 목록), 미국 증시(규칙 계산),
  미국 국채(증시 휴장일 + 컬럼버스데이·재향군인의 날).
- **목록이 없는 시장**(도쿄·상하이·홍콩·선물) — 공휴일을 모릅니다. 대신 개장
  시간인데 마지막 체결이 1시간 넘게 멈춰 있으면 **"휴장 추정"**으로 낮춥니다.
  멈춤은 "지금"이 아니라 **수집 시각** 기준으로 잽니다. 수집기가 멈춘 것을
  시장 휴장으로 오인하지 않기 위해서입니다. 체결 시각이 없는 카드(TradingView)는
  시간표만으로 판정하고, 배지 툴팁에 "현지 공휴일은 반영하지 않음"을 적습니다.
- 조기 폐장·임시 휴장·악천후 휴장은 다루지 않습니다.
- `marketSessions.check.mts`가 점심 휴식, 자정을 넘는 야간장과 그 휴장일 귀속,
  정비 시간, 휴장 추정을 검증합니다.

## 모든 숫자에 출처를 적습니다

화면의 데이터 카드는 전부 "출처 · …" 줄을 갖습니다(`Card`·`Metric`의 `source`). 문구는
`frontend/src/lib/sources.ts` 한 곳에 모읍니다 — 화면마다 따로 적으면 같은 출처가 다른 이름으로
불립니다. 규칙:

- 기관 이름과 **성격**(공식·비공식·추정·대시보드 계산)을 함께 적습니다.
- 백엔드·수집기가 출처를 내려주면 그 값을 씁니다(레이더 순위·재무·금융위·토스·매크로 카드).
  매크로 카드는 수집기가 카드마다 `Yahoo Finance (티커)`를 붙이고, 미국채처럼 다른 출처로 덮어쓴
  카드는 그 출처로 바뀝니다.
- 수집이 실패해 추정치로 대체되면 출처도 바뀌어야 합니다(예: KRX 선물 → "KODEX 200 기반 추정치").
- 입력·설정용 카드(선택 상자만 있는 카드)에는 출처를 달지 않습니다.

## 날짜 기준은 한국(KST)입니다

컨테이너의 기본 시간대는 UTC입니다. `LocalDate.now()`를 그대로 쓰면 한국 시각
00:00~09:00 사이에 **날짜가 하루 어긋납니다.** 실제로 섹터 화면의 연초 대비
수익률(YTD)이 1월 1일 오전에 전년도 기준으로 계산됐습니다 — 예외도 빈 값도
없이 그냥 틀린 숫자가 나오는 종류입니다.

백엔드는 `com.macrodash.Kst.today()`를 씁니다. JVM 기본 시간대를 바꾸지 않는
이유는, 기본값을 건드리면 라이브러리가 조용히 영향을 받고 어디서 바뀐 것인지
추적하기 어려워지기 때문입니다.

### 화면의 시각은 한 형식입니다 — `YYYY-MM-DD HH:mm`

초는 쓰지 않고(수집 주기가 분 단위라 초는 잡음), 날짜는 항상 씁니다. `23:33:00 KST`처럼
시각만 적으면 자정을 넘기거나 휴장일이 끼었을 때 어느 날 값인지 알 수 없습니다. 형식은 세 계층이 같은 한 곳씩에서 만듭니다.

| 계층 | 위치 |
|---|---|
| 수집기 | `collector/app/kst.py` `stamp()` |
| 백엔드 | `Kst.DISPLAY` · `Kst.stamp()` |
| 화면 | `lib/format.ts` `formatKst()` — DB에 저장된 다른 형식·ISO(UTC)도 같은 모양으로 맞춤 (`npm run check`가 고정) |

## 날짜와 값은 짝지어 읽습니다

저장본은 `{"dates": [...], "close": [...]}` 모양입니다. 두 배열을 **따로**
걸러 내면 안 됩니다.

```java
// ❌ 종가 한 칸이 null이라 그 칸만 빠지면, 이후 모든 날짜가 한 칸씩 밀립니다.
List<Double> closes = doubles(series, "close");   // null 제외 → 99개
List<LocalDate> dates = dates(series);            // 그대로   → 100개

// ✅ 한쪽이라도 비면 그 칸을 통째로 버립니다.
Series aligned = alignedSeries(series, "close");
```

밀린 배열은 예외를 내지 않습니다. "21 거래일 전"이 실제로는 22일 전이 되어
**조용히 틀린 수익률**이 나올 뿐입니다. `SectorSeriesAlignmentTest`가 고정합니다.
