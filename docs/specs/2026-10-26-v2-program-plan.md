## 0. 한 줄 목적

`My_macro_dashboard_v1`을 갈라낸 `My_macro_dashboard_v2`에서 **(1) 화면을 Coinbase식 패턴으로 새로 쓰고, (2) 한국 증시 모의 알고리즘 매매 책을
더하고, (3) 세 오픈소스에서 검증된 정의·출처·안전 패턴을 옮기고, (4) 로컬에서 끝낸 뒤 AWS의 v1을 v2로 교체**한다.
백엔드·수집기·DB 스키마는 이어받는다. 지금까지의 정확성 규칙(ADR 19장·PRINCIPLES·테스트)을 다시 쓸 이유가 없다.

## 3. 변하지 않는 원칙

PRINCIPLES.md와 ADR 0001~0019 전부. 이 프로그램에서 특히 자주 걸리는 것:
- **없는 숫자를 만들지 않는다** — 새 화면도 빈값 `—`, `isEstimated`·`isProxy`·`isStale` 배지, 축 정직, 색만으로 의미 전달 금지
- **모의매매 상태는 한 곳에만**(ADR 0019) — 로컬 v2는 `PAPER_ENABLED=false`. AWS 교체 때 상태를 **한 번만** 옮기고 v1을 바로 멈춘다
- **제안은 모델, 검증·집행은 코드**(ADR 0018) — 숫자 근거 검사(3단계)도 집행을 바꾸지 않는다
- **테이블마다 쓰는 프로세스 하나, 스키마는 `db/migrations` 한 곳**(ADR 0008) — 번호는 v1에서 이어 간다(V13부터)
- **수집기는 받아 저장만, 계산은 백엔드 `analytics`**(ADR 0001) — 옮겨 오는 알고리즘은 전부 `analytics`(java.*만)에 순수 함수로, 기대값 테스트로 고정
- **새 API 경로는 `AccessPolicy` 표에**(ADR 0010) — 한국 책 경로는 모두 운영자 전용

### 3단계 — Claude 책 공통 고도화

1. `analytics.FigureCheck`: 응답 글(`summary`·`thesis`·`exposureRationale`) 속 숫자를 보낸 패킷의 숫자 집합과 상대 0.5% 또는 적힌 자릿수 반 단위로 대조 → 일치·불일치·미확인 개수를 결정 행에 기록, 화면 배지, 복기 입력에 포함. 불일치가 있으면 **교정 재호출 1회**(상한 안) — 집행은 바꾸지 않는다
2. 결정 스키마 v3: `bearCase`(반대 논거) 필드 추가. 투자위원회식 다중 호출은 하지 않는다
3. 스코어카드 재무 팩터: `us.fundamentals`로 이익수익률·FCF 수익률·장부가/시가·ROE·GP/TA·발생액·Piotroski F — 유니버스 내 백분위, 원자료 함께, "종합 점수 아님" 유지
4. 뉴스 군집(제목 토큰 Jaccard ≥ 0.25·24시간)과 "3개 이상 출처" 표시 → 패킷 `11b_events`는 군집 대표만
- 적용 시점: 1·2는 미국 책의 실험 조건을 바꾸므로 **한국 책 출발일에 함께** 적용하고 설정·프레임 판 번호로 기록

### 5단계 — 분석 고도화와 우회 수집

1. Brinson-Fachler + Carino 연결: Claude 계좌 vs 규칙 계좌(섹터 배분·종목 선택·교차). SPY 대비는 섹터 비중 출처가 생긴 뒤
2. BIS SDMX(신용갭·DSR·정책금리·주택가격, 한국 포함) → `timeseries` → 매크로 참고 카드. 국면 판정 입력에는 넣지 않는다
3. 규칙 계좌 walk-forward(purged 분할·블록 부트스트랩 CAGR 신뢰구간·PSR·증거 등급) — 후보 기관 30분기 수집 완료 뒤
4. 우회 수집(V2 결정 뒤): KRX 정보데이터시스템 전 종목 투자자별·공매도, 네이버·FnGuide 국내 컨센서스 — 수집기 태스크가 필요할 때만 띄우는 one-shot 헤드리스. 상주 REST 서버는 올리지 않는다

## 5. AWS 교체 절차 (4단계)

같은 EC2 `my-macro-app` 한 대를 쓴다. 새 인프라를 만들지 않는다. **토요일 창(~10:00 KST)**에 한다 — 미국 세션이 없어 체결을 놓치지 않는다.

1. 전날까지: v2 `main`이 CI 녹색, 로컬 QA 스택에서 `make restore F=<v1 최신 백업>` 뒤 화면·결정 미리보기 확인(호출 상한 안에서 1회)
2. 서버에서 v1 폴더: 정기 작업이 도는 중이 아닌지 확인(`/paper` 작업 기록) → `make backup` → 백업 파일 행 수 기록 → `make down`
3. 서버에 v2 폴더 clone(`~/My_macro_dashboard_v2`), `.env`는 v1 것을 복사해 `.env.aws.example`대로 고침(포트는 서버 기본, `PAPER_ENABLED=true`, `LOCAL_NO_LOGIN` 덧붙임이 `false` 고정)
4. `bash scripts/aws/deploy.sh`(이미지 하나씩 빌드, 4 GiB) → `make migrate`가 V13까지 적용 → `make restore F=<2의 백업>`
5. 설정 화면에서 `apiDailyCallCap` 20 확인(복원된 DB 값은 v1의 6), 미국 책 순자산·보유·마지막 결정이 백업과 같은지 확인
6. cron의 `backup-s3.sh` 경로를 v2 폴더로, 터널 스크립트 확인, ADR 0019·CLAUDE.md 갱신
7. 되돌리기: v1 폴더와 볼륨은 지우지 않는다. 문제가 생기면 v2 `make down` → v1 `make up`. 교체 뒤 v2에서 생긴 기록은 v1에 없다는 점을 적어 둔다
8. 한 주 뒤 첫 사이클(결정·체결·복기·백업)이 확인되면 v1 폴더를 서버에서 지운다(볼륨은 백업 확인 뒤)

## 6. 위험과 대응

| 위험 | 대응 |
|---|---|
| 두 곳에서 정기 작업이 동시에 돈다 | 로컬 v2는 `PAPER_ENABLED=false` 고정. 교체 때 v1 `make down`을 먼저. 기동 로그에 `PAPER_ENABLED` 값 출력 |
| UI 전면 교체 중 숫자 원칙이 깨진다 | 공용 컴포넌트에 원칙을 넣고(빈값·배지·축) 화면마다 네 상태 스토리 고정. 화면 DoD에 PRINCIPLES 체크리스트 |
| 36k줄 이식이 끝나지 않는다 | 화면 단위로 끝내고 옛 화면은 v2에 두지 않는다. 1단계는 두 화면만, 나머지는 4단계 |
| 한국 가격이 '오늘'이 없다(금융위는 익일 13시) | 관측치는 토스 일봉, 확정 종가는 금융위로 역할을 나눈다(명세 K4). 서버가 장중에 꺼져 있어 장중 관측치는 없다고 화면에 적는다 |
| 결정 프롬프트·스키마 변경이 실험을 흔든다 | 한국 책 출발일에 한 번에 적용, 설정·프레임 판 번호와 결정 기록에 남긴다 |
| 우회 수집이 서버 메모리를 넘친다 | V2 결정 전에는 하지 않는다. one-shot 방식, 컨테이너 상한, 실패 시 이전 값 유지 |
| 호출 비용 | 상한 20 × 약 $0.09 = 하루 최대 약 $1.8. 추정 비용은 `paper_api_usage`에 그대로 쌓인다 |
| 외부 비공식 엔드포인트(TradingView 캘린더 등)가 바뀐다 | ADR 0017과 같은 '비공식 참고' 지위, EmptyResult로 이전 값 유지, 화면에 출처·시각 |

## 7. 측정 — 넣기 전에 정한다

- 단계마다 완료 정의는 위 수용 기준이다. 수용 기준이 없는 작업은 시작하지 않는다
- 성능: 교체 전 `ENV_FILE=.env.qa bash scripts/bench-api.sh`로 v1과 v2의 주요 경로 응답 시간을 같은 데이터로 비교해 기록
- 비용: AWS 월 예산 알림(45 USD)은 그대로. t4g.large로 가면 월 약 $30(인스턴스 2배)으로 다시 계산
- 결정 품질: 3단계 뒤 숫자 근거 검사의 불일치율을 주간 복기에 넣어 추세를 본다
