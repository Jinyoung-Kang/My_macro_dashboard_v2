## 1. 목표와 하지 않는 것

### 목표
1. **한 가지 화면 언어**: 정보 검색과 같은 어두운 면, 4px 모서리, lg 이상 30px 조작, 표 행 28~32px를 모든 메뉴에 씁니다. '밝은 셸 안의 어두운 섬'과 '두 가지 어두움
   (`#0a0b0d`와 `#111418`)'을 없앱니다.
2. **대상 중심**: 지표, 종목, 기관, 모의 계좌, 결정, 프레임 판, 출처(조사 시점 69곳)를 '열 수 있는 대상'으로 다룹니다. 화면은 목록 → 오른쪽 검사 칸 → 대상 화면(full) 문법을 공유합니다.
3. **밀도와 길이**: 첫 화면에 실제 데이터를 더 보이게 합니다. 아주 긴 한 줄 화면(프레임 27~28k px, 매크로 22k, 설정 20k, 저장소 상태 13k)은 목차, 목록-검사, 기본 접힘으로 쪼갭니다.
4. **메뉴를 한 겹으로**: lg 이상에서 왼쪽 메뉴·하위 메뉴 줄·더보기·모의매매 안 탭의 세 겹을 나무 메뉴·빵부스러기·명령 팔레트로 정리합니다(W2).
5. **쓰기 동작 분리**: 읽는 화면에 섞인 쓰기 단추('일시정지'·'계좌 초기화', '지금 결정 실행', 스타일 카드의 '새로고침')를 머리의 '동작' 영역으로 옮깁니다.
   확인 절차, 문구의 뜻, API는 그대로입니다. 셸의 '데이터 수동 새로고침'도 쓰기(운영자 전용 수집 요청 `POST /api/status/refresh`)로 보고, 화면 머리가 아니라
   lg 이상은 상단바의 아이콘 단추, lg 미만은 지금처럼 더보기에 둡니다(§5). 명령 팔레트에는 넣지 않습니다.
6. **접근성 결함 정리**(조사 시점 숫자, [확인] 코드·운영 화면 DOM 측정):
   - 12px 미만 글자: ▲▼가 `components/patterns/ChangeChip.tsx`의 `text-[0.8em]`으로 10.4px(홈 27개, 모의 개요 6개), `components/screens/detail/DetailParts.tsx`의 AI 요약
     위첨자 `text-[11px]` 2곳(기준 커밋 297·301행).
   - lg 미만에서 44px 미만인 누름 자리: 정보 수집 뉴스 49개, 종목 상세 22개, 설정 체크박스 13px.

   이 결함들을 결함 번호를 받아(P0에서 QA-457·QA-458로 고침 — 시험 `lib/__tests__/fontFloor.test.ts`·`touchTargets.test.ts`) 고치고 소스 검사 시험으로 다시 생기지 않게 막습니다.

### 하지 않는 것
- API 경로, `AccessPolicy` 등급, 백엔드와 수집기 코드는 바꾸지 않습니다(V1). 메뉴 표 `lib/nav.ts`의 `TABS` 항목과 순서도 그대로이고 그리는 방식만 바꿉니다.
- 모의 매매·실제 매매·ISA의 **동작**은 바꾸지 않습니다: 탭 전환의 `history.replaceState`, 실제 매매 끄기 단추가 늘 닿는 규칙(SEC-6), 확인 글자와 비밀번호, POST 시간 한도
  (QA-345), 경계 시험, 패킷과 프롬프트의 고정본.
- 옛 화면 경로 이식(프로그램 4단계)은 하지 않습니다(W9). Blueprint 패키지(`@blueprintjs/*`)·아이콘 파일·웹폰트는 넣지 않습니다(ADR 0041 대안, W8).
- 숫자 원칙(PRINCIPLES)은 바꾸지 않습니다. 값이 없으면 '—', 추정·대리·이전 값 배지는 늘 보이고, 출처 줄도 남깁니다. 밀도를 위해 배지나 출처를 숨기는 옵션은 만들지 않습니다.
- 화면 문구의 뜻(용어, 판정 글)은 바꾸지 않습니다. 긴 설명 문단은 지우지 않고 '자세히' 접기나 '?' 도움말로 옮깁니다.

## 3. 디자인 시스템

### 3-1. 그대로 지키는 원칙
- **A1**: 강조 파랑(accent)은 누를 수 있는 것에만 씁니다 — 주 단추, 링크, 현재 메뉴, 포커스, 알림 수. accent `#4c90f0`과 down `#68c1ee`의 OKLab ΔE가 14.1로 15 미만이라
  [계산] 색만으로는 구분되지 않습니다.
- **D4**: 상승은 빨강, 하락은 파랑. 등락은 ▲▼, U+2212, sr-only 글로도 전합니다(A2). Blueprint의 초록·빨강 의도색은 등락에 쓰지 않습니다.
- **상태색**(ok·warn·danger)은 늘 아이콘과 글을 함께 씁니다. 새 상승색과 위험색의 ΔE는 4.4로 사실상 같은 색입니다(§3-2-1).
- A2~A10, 한국어 라벨, 이모지 금지, ADR 0004 층 규칙, 네 상태 시험(값 있음·없음·추정·오래됨)은 그대로입니다. Coinbase 명세의 A4(격자 없음·히어로 단일 선)는 W6·W7이,
  A9의 '히어로와 목록은 넉넉하게'는 §3-7이 고칩니다.

### 3-4. 의도색 쓰는 법
- **단추 네 종류**: 기본(surface-2와 border), 주(accent 바탕 — 한 묶음에 하나), 위험(danger 바탕 — 확인 대화상자를 거치는 파괴적 동작에만, 늘 글), 최소(투명 — 표 안·도구 줄).

- **상단바 48px**: 왼쪽 앱 이름 · 빵부스러기(메뉴 › 하위 화면 › 대상 — `lib/breadcrumbs.ts` 순수 함수가 `nav.ts`에서 계산) · 오른쪽 명령 팔레트 입력(Ctrl/⌘K), **데이터 새로고침
  아이콘 단추**(이름 있음 — 지금 왼쪽 메뉴의 파란 주 단추를 옮김. 수집을 일으키는 쓰기라 지금처럼 운영자에게만 보이고(`isOwner`, 백엔드도 403), 결과 안내 문구
  (`role="status"`)도 남김), 장 시계(KOSPI·NASDAQ), 알림 벨, 계정 메뉴(읽기 모드와 빌드 정보를 그 안으로).
- **왼쪽 나무 메뉴 220px**: 메뉴 7개, 현재 메뉴의 하위 항목을 펼침 — 그래서 **lg 이상의 하위 메뉴 줄(`SubNav`)은 없앰**. 항목 높이 32px, 현재 항목은 3px 막대(`SELECTED_BAR`와 같은 폭)·굵기·`aria-current`

- **본문**: 화면이 칸 틀을 정합니다(공용 `SplitPane`/`MasterDetail` — 목록 / 가운데 / 오른쪽 검사 칸, 맨 아래 공용 출처 상태 줄 `SourceStatusLine`). `main#main`의 본문 건너뛰기,
  `relative`, `min-w-0`, lg 미만 `overflow-x-clip`·lg 이상 `overflow-x-hidden`(QA-450)은 유지합니다.

- 상단바는 지금 구성 그대로입니다: 위 줄(64px)에 앱 이름·검색·알림 벨, 둘째 줄에 장 상태 칩(KOSPI·NASDAQ — 넘치면 그 줄만 가로 스크롤). 빵부스러기는 넣지 않고,

**명령 팔레트** — 지금 `components/shell/SearchCommand.tsx`(한글 자판 물리 키 처리 포함)를 넓힙니다.

### 8-4. 커밋 순서 규칙
1. **옮기는 커밋과 고치는 커밋을 나눕니다** — 예: `search/parts.tsx` 조각을 `ui/classes.ts`로 옮기는 커밋(겉모습 변화 0) → 값을 고치는 커밋.
2. **이름만 바꾸는 커밋**(옛 별칭 codemod)에는 다른 변경을 섞지 않습니다. 화면 diff가 클래스 이름 바꾸기뿐이어야 합니다.
3. **색 hex가 바뀌는 커밋에서 hex 고정 시험을 같이 고칩니다**(조사 시점: `lineChart`, `LineChart`, `wrappers`, `DonutChart`, `paperOverviewStates`, `paperAccountDetail`,

4. **겉모양 단언은 그 겉모양을 바꾸는 커밋에서 고칩니다.** 뜻을 보는 단언(role, aria, sr-only, `text-up`/`down`/`warn`, `tabular-nums`, '—', 배지)이 시험 diff에 나오면 그 커밋을
   멈추고 다시 봅니다. 모의매매·실제 매매·ISA·데모 열람 동작 시험은 바꾸지 않습니다.
5. **결함은 `test(QA-###)` → `fix(QA-###)` 두 커밋**(수정 전 `it.fails`). 번호는 그때 남은 다음 번호(P0 뒤 QA-459부터).
6. 큰 파일은 고치러 들어간 부분만 떼어 냅니다. 코드 주석의 Coinbase 언급은 고치러 들어간 파일에서만 고칩니다.
7. 커밋 메시지는 `type(scope): 한국어 요약` + `Co-Authored-By` 줄, 이모지 없음, 참고한 디자인 시스템을 만든 회사·제품 이름 없음.
8. 순서 안에서: 토큰 → 키트 → 셸 → 화면(메뉴별) — 화면 커밋은 그 화면 파일과 그 화면 시험만 건드립니다.

   두 어두운 면 위 3:1을 셉니다. 문서(§3-5 표)는 파싱하지 않습니다 — 버린 값·바꿀 값·아직 돌리지 않은 묶음이 글로 섞여 있어, 문서를 고칠 때마다 깨지거나 버린 hex를
   기대값으로 잡을 수 있기 때문입니다. 검증기 원본은 저장소 밖이라 실행 결과(색약 ΔE·대비)는 §3-5에 기록만 합니다.
   → `frontend/src/lib/__tests__/paletteRecord.test.ts`(P2 마무리 2026-11-16 — 기록한 파일 밖의 hex 색 글도 막음).
5. **데이터 칸 강조색 금지(새)**: 데이터를 그리는 패턴(`KpiStrip`·`PropertyList`·`DenseTable` 값 칸·`Timeline`·`AssetRow`·`Sparkline`)과 차트 소스에 `accent` 토큰이 없는지(A1).
   범위의 정확한 파일 목록은 P0 시험 커밋이 정합니다.
   → `frontend/src/lib/__tests__/accentInData.test.ts`(P2 마무리 2026-11-16 — 지금 있는 데이터 패턴과 차트 셋, 새 데이터 패턴은 들어오는 단계에서 목록에 더함, §8-2).
   공용 키트의 `Table`·`Metric`(DenseTable·KpiStrip의 '지금' — 단추·링크와 한 파일)은 파일이 아니라 그 함수 몸통만 봅니다(검토 지적으로 더함, `deltaColor` 포함).
6. **명령 팔레트의 쓰기 동작 금지**: 팔레트 항목 목록에 POST를 부르는 동작이 없음을 단언합니다(P3). 예외는 없습니다 — 데이터 새로고침(`POST /api/status/refresh`)도
   팔레트에 넣지 않습니다(§5).
7. **겉모양과 뜻의 분리**: §8-4의 4번.
8. **구조 시험 유지**: `ArchitectureRulesTest`, 프런트 층 시험, `patterns/__tests__/index.test.ts`, `frameBoundary`, 경계 시험 3개, `noEmoji`, `endpoints`, `nav.test`, `a11y.test`,
   `demoViewer.test`, `realTradeScreen.test`. 셸 시험(`Shell`, `MoreMenu`, `ThemeSwitch`)은 W1·W2대로 다시 씁니다.
9. **브라우저 확인(W11)**: QA 스택(`bash scripts/qa/qa-stack.sh up`)에서 브라우저 캡처와 DOM 감사.
   - 감사 항목: 12px 미만 글자, 44px 미만 누름 자리, 가로 넘침, 계산 대비. 감사 스크립트는 `scripts/qa/ui-audit.js`(의존성 없음)로 저장합니다.
   - **캡처에는 모의 장부 금액이 있으므로 저장소에 커밋하지 않습니다.** 전후 비교는 scratchpad의 캡처와 docs/qa의 숫자 기록(감사 결과)으로만 남깁니다.
   - **개편 전 기준은 P1을 시작하기 전에 QA 스택에서 다시 잽니다** — 같은 감사 스크립트와 같은 폭(390·1440)으로 캡처와 DOM 감사 숫자를 만들고, 숫자는 docs/qa에
     기록합니다. 조사 때의 92장은 운영 화면(데이터가 다름)이고 캡처가 세션 작업 폴더에만 있어 전후 비교 기준으로 쓰지 않습니다. 그 DOM 숫자는 참고값으로 진행 기록에 옮겨 둡니다.
10. **성능**: 경로별 First Load JS(`next build` 출력)를 단계마다 비교합니다. 매크로 317행, 프레임 156k자, 저장소 상태 183행은 기본 접힘과 목차로 DOM을 줄입니다. 가상화 의존성은 넣지 않습니다.
