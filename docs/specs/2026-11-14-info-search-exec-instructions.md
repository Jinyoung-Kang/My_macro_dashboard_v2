# 실행 세션 지시문 — 메뉴 재배치와 정보 검색(대상 중심 검색 · 관심 대상) (2026-11-14, 4판)

## 1. 역할과 목표

너는 이 프로젝트를 넘겨받은 시니어 풀스택 엔지니어야. 이 작업은 두 세션으로 나뉘어 있어. 계획 세션(2026-11-14)이 지금 구현과 외부 출처, 참고 오픈 소스를
확인해 이 지시문을 썼고, 이 세션은 그것을 실행하는 세션이야. 너는 계획 세션의 대화를 볼 수 없어. 이 지시문, 프롬프트, 저장소의 문서와 코드가 네가 아는 전부야.

목표는 셋이야.

- 작업 M — 메뉴 재배치: 왼쪽 메뉴를 홈 · 시장 · 기관 · 모의매매 · 정보 검색 · 정보 수집 · 더보기 순으로 바꾸고, '한국' 탭의 두 화면을 더보기 안으로 옮김.
- 작업 S — 새 메뉴 '정보 검색': 기업·기관 이름(NVIDIA·엔비디아·NVDA, 삼성전자·005930, Duquesne Family Office·듀케인 패밀리 오피스)이나
  사람 이름(Ken Griffin·Kenneth Cordele Griffin, Elon Musk)을 넣으면 그 대상의 기사·공시·보고서·논평·에세이·블로그를 **최근 2년 안에서** 최신순으로 모아 보여 줌.
  상단 통합 검색(메뉴·지표·기관·종목 찾기)과는 다른 기능이야. 종목 차트는 넣지 않아.
- 작업 W — 관심 대상: 대상을 등록해 두면 서버가 그 대상의 새 글을 낮은 빈도로 모아 두고, 화면이 새 글 수를 보여 줌.

§2의 사용자 결정과 §8의 지킬 것은 고정이야. §4~§6은 계획 세션의 권장 설계라 코드와 실측에 맞게 고쳐도 돼(고친 이유를 진행 기록에 적어).

## 2. 사용자 결정 (2026-11-14 — 고정)

- 네이버 검색 API 키는 발급하지 않아. 네이버 검색 API(네이버 API 허브)는 쓰지 않음.
- 정보 검색은 운영자 전용이 아니야. 이 프로젝트에 접속한 사용자가 쓸 수 있게 함(등급 해석은 결정 D-1).
- 정보 수집 탭은 정보 검색 바로 뒤, 더보기 앞에 둠(좁은 화면에서는 지금처럼 더보기 안).
- 더보기 화면에서 한국 시장 화면(수급 레이더 · 파생·투기세력)을 제목으로 나눠 보임.
- 출처는 공식 API 또는 스크래핑. 봇 차단을 지나가는 수집을 써도 됨. 악성 봇으로 오인되지 않게, 상대 서버에 악성 트래픽·과부하를 주지 않게, 사람처럼 행동하게.
- **스크래핑하는 곳은 Finviz의 종목 뉴스·블로그 하나야(승인 범위).** 다음은 스크래핑하지 않아 — 네이버 뉴스 검색 화면, 네이버 증권 리서치 목록, 한경 컨센서스,
  중국 자본이 소유한 사이트.
- **FinceptTerminal 피드 목록에서 우리에게 없는 RSS(중앙은행·규제기관 보도자료, 미국·유럽·일본 경제지)를 승인 범위에서 넣어**(§4.8).
- **최근 2년치만 조회해.** 2년 안에 자료가 없으면 "최근 2년 안의 자료가 없습니다"라고 안내하고, 2년보다 오래된 것만 있었다면 가장 최근 날짜 하나를 함께 적어(그 줄들은 보이지 않음).
- **관심 대상 등록 기능을 넣어.** 상한은 사용자당 회원 10개·운영자 50개, 서버 전체 100개. 서버는 대상당 3~8시간에 한 번 모아(초기값).
  알림은 화면의 새 글 수만 — 알림함 연결은 단계 6, 텔레그램은 넣지 않음.
- **겉모습은 팔란티어처럼, 테마는 어둡게 고정.** 정보 검색 화면은 앱의 밝음·어두움 설정과 상관없이 늘 어두운 테마야. 기업 종목 차트는 띄우지 않음.
- **중국어 자료와 중화권 출처는 일체 쓰지 않아.** 중화권 기반 사이트와 중국 자본이 소유한 사이트를 직접 부르지 않고, 중국어 판·중국어 별칭으로 묻지 않고,
  돌아온 결과에 섞인 중국어 글은 빼. 소유나 기반이 애매한 출처는 넣지 말고 보고해. 결과에 섞여 온 중화권 영어 매체는 D-9를 따라.
- 오픈 소스 `akfamily/akshare`·`akfamily/akquant`·`Fincept-Corporation/FinceptTerminal`은 그 코드가 쓰는 **데이터의 출처와 수집 방식을** 이 프로젝트에 맞게 접목해.
  코드를 어떻게 다룰지는 사용자가 세 길을 열어 뒀어 — 저장소를 비공개로 바꿈(예정이지만 미정), 그 오픈 소스의 라이선스를 따름, 그대로 복사하지 않고 고쳐 써서 자기 코드로 만듦.
  이 지시문은 그 안에서 가장 안전한 길을 기본으로 잡았어(§8의 오픈 소스 규칙, D-10).
- 이 프로젝트는 개인·비상업·학술 용도야(접속은 Tailscale 안).

## 3. 계획 세션이 확인한 사실 (2026-11-14, `main@a7ca2063` 기준)

코드 위치는 파일과 심볼로 가리켜. 실행하기 전에 지금 코드에서 다시 확인해.

### 메뉴
- 메뉴 표는 `frontend/src/lib/nav.ts`의 `TABS` 하나야(셸·브라우저 탭 제목·통합 검색이 함께 씀). 지금 순서는 홈 · 시장 · 기관 · 한국 · 모의매매 · 정보 수집 · 더보기.
  한국 탭의 화면은 `/radar`(수급 레이더)·`/krx`(파생·투기세력) 둘.
- 보이는 메뉴는 `frontend/src/lib/access.ts`(`OWNER_ONLY_MENUS`에 `/paper`·`/info`). 좁은 화면 탭 바 `components/shell/TabBar.tsx`는 정보 수집을 빼고 그리며
  칸 수 표 `COLUMNS`에 5·6만 있어. 더보기 화면 `components/shell/MoreMenu.tsx`는 정보 수집을 맨 위 행으로 넣어. 아이콘은 `components/shell/icons.tsx`.
- 시험: `frontend/src/lib/__tests__/nav.test.ts`(탭 순서·소속), `components/shell/__tests__/Shell.test.tsx`·`MoreMenu.test.tsx`.

### 지금 있는 검색·뉴스·저장본·알림
- 상단 통합 검색: `frontend/src/lib/search.ts`·`components/shell/SearchCommand.tsx`. 명세 `docs/specs/2026-11-01-search-detail.md`.
- 종목 상세의 뉴스: 수집기 `collector/app/services/detail.py`의 `news()` — 구글 뉴스 RSS(`when:7d` 고정), Yahoo(yfinance `Search`), 네이버 종목 뉴스(모바일 JSON API), 연합인포맥스.
  합쳐 최신순 20건(`merge_news`), 15분 메모리 캐시, DB에 남기지 않음. `/live/news`·`/live/quote`·`/live/symbols` → 백엔드 `feature/detail` →
  `GET /api/detail/news|quote|symbols`(회원), `POST /api/detail/summary`(유료). 국내 종목의 리포트 칸(`quote.research`)도 이 응답에 이미 있어.
- 사건 뉴스 RSS: `collector/app/services/news.py`의 `FEEDS`(미국 — Investing.com 네 개, 연준 통화정책 보도자료 `press_monetary.xml`, BLS CPI·고용, SEC 보도자료)와
  `KR_FEEDS`(한국은행·재정경제부·국가데이터처·연합뉴스 시장). 관측치 `news_headline`·`kr_news_headline`(7일), 탄력 주기와 조건부 요청은 ADR 0040
  (`collector/app/tasks/news_feeds.py`·`flex.py`). **이 두 묶음은 모의 매매 결정 패킷의 사건 섹션이 읽어.**
- 정보 수집(ADR 0035~0037): 표 `info_items`(해외 블로그 14곳·waedge 글·Financial Juice 속보), 거장 견해(101명).
  `GET /api/info/items?q=`는 제목·한국어 제목·요약만 찾아(`store/InfoStore.java` — 본문 검색 없음). `/api/info/*`는 모두 운영자 전용.
  출처 표는 백엔드 `feature/info/InfoSources`(수집기 태스크와 `InfoSourcesParityTest`가 대조).
- 13F: `GET /api/sec13f/institutions`(이름·CIK·운용자 소개), `GET /api/guru/holders?q=`, `GET /api/sec13f/portfolio`.
- DART: `collector/app/services/dart.py`는 재무 주요계정만(종목코드 → 고유번호 표 받기는 있음, `DART_API_KEY`). SEC는 연락처가 든 `SEC_USER_AGENT` 필수.
- 알림: `backend/.../feature/alert` — 사용자별 규칙(`alert_rules`)·사건·알림함(`alert_deliveries`, 채널 `inbox`), 등급별 상한, 상단바 종 아이콘의 읽지 않은 수.
- 수집기가 백엔드 표를 읽기만 하는 선례: `collector/app/store.py`의 `paper_settings` 읽기(ADR 0008·0032). 표 소유 시험은 `collector/tests/test_table_ownership.py`와
  백엔드 `ArchitectureRulesTest`. 스키마는 `db/migrations/`(지금 끝은 V36).
- 저장소: GitHub 공개 상태이고 라이선스 파일이 없어(2026-11-14 `gh repo view`).

### 차단 통과 수집 계층 (ADR 0026·0035·0037, `collector/app/fetch/`)
- 계층: 불규칙 간격·하루 예산 → 브라우저와 같은 TLS·헤더(`curl_cffi`) → 요청마다 띄우는 실제 브라우저(`collector/sidecar`, 서버의 `browser` 컨테이너).
  거부되면 한 번만 위 계층으로 올라가고, 거부가 쌓이면 물러났다가 포기해. 진입점은 `ladder.fetch` 하나.
- 호스트마다 브라우저 프로필 하나를 고정하고, 같은 호스트의 요청 사이는 4~15초(가끔 20~45초). 정책 표(`policy.POLICIES`)에 없는 호스트는 받지 않고,
  계층 2를 쓰는 호스트는 `compose.vultr.yml`의 `BROWSER_ALLOWED_HOSTS`와 같아야 해(시험이 대조).
- 운영 서버에서만 켜져(`POLITE_FETCH_ENABLED` — 로컬·QA compose는 `"false"` 고정). 프록시·IP 돌려쓰기는 없고, 사람 확인은 입력 없는 체크박스만 한 번 누르며,
  서버 IP가 막히면 그 출처를 포기해. 비주기 일정은 `collector/app/tasks/polite.py`의 `Cadence`(다음 실행 시각을 표 `fetch_schedule`에).
- **지금은 polite 속도군 태스크만 이 계층을 불러.** 화면의 요청이 이 계층을 부르는 길은 없어 — Finviz가 처음 만드는 길이야(§4.6).

서버 IP에서의 응답은 다를 수 있어 — 단계 0에서 서버에서 한 번씩 다시 봐. 막히거나 멈춘 피드는 빼고 보고해. 각 매체의 소유가 중국 자본인지는 계획 세션이 확인하지 않았어 — 넣기 전에 확인해.

### 참고 오픈 소스 (2026-11-14 — 사본을 저장소 밖에 받아 읽기만 함, 어떤 코드도 실행하지 않음)
라이선스(GitHub API): akshare·akquant는 MIT, FinceptTerminal은 AGPL-3.0. 아래 주소·상수는 계획 세션이 코드에서 직접 대조한 것이야(파일 경로는 그때 기준).
앞선 검토는 `docs/specs/2026-10-26-v2-oss-adoption.md`에 있어.

- **akshare** — 화면 뒤의 JSON 주소를 직접 부르는 방식의 금융 데이터 모음. 한국 종목·뉴스·공시를 다루는 인터페이스가 없고 영어 뉴스도 없어 —
  뉴스·속보·프로필·목표가 목록의 출처가 전부 중화권 사이트라 **사용자 결정으로 출처는 하나도 쓰지 않아.** 남는 것은 수집 방식뿐이야:
  공용 HTTP 모듈 하나(`utils/http.py`)로만 나감, 지수 간격 + 흔들림 재시도, 차단을 감지하면 재시도하지 않고 멈춤, 쪽 사이 0.5~1.5초 쉼.

- **akquant** — Rust·Python 백테스트 엔진. 자체 정보 출처가 없어(데이터는 akshare의 중국 A주 일봉). 이 작업에 접목할 것이 없어.
- **FinceptTerminal** — 한국 전용 출처는 없음(DART·KRX·네이버·한국 RSS 없음).

    (키 없음, 연락처 UA — `scripts/Analytics/corporateFinance/deal_database/deal_scanner.py`). 계획 세션은 이 주소를 직접 불러 보지 않았어.
  - GLEIF LEI `api.gleif.org/api/v1/lei-records?filter[fulltext]=…`와 모회사·자회사 경로(`scripts/lei_data.py`) — 법인의 소유 관계.
  - 관계도는 전부 yfinance(`institutional_holders`·`insider_holders`·`insider_transactions`·임원·`upgrades_downgrades`·`calendar` — `scripts/relationship_map.py`).
    동종 기업은 손으로 적은 표라 쓰지 않아.
  - 뉴스: RSS 53개(`src/services/news/NewsService_Feeds.cpp` — 위 후보 표의 출처), 같은 글 가리기(정규화한 링크의 해시), 군집(제목 토큰 Jaccard 0.25 — 같은 분류면 0.20, 24시간),

  - 키워드 감시(`NewsMonitorService`): `{이름, 키워드들, 켬}` — 제목+요약에 단어 경계로 대조, 감시:글 키로 한 번만 알림, 받은 지 30분 넘은 글은 알리지 않음.
  - 그 저장소의 수집기는 재시도·robots 처리가 없고 브라우저 UA만 흉내 내 — 수집 예절은 우리 계층이 더 엄격해. 예절은 거기서 배우지 않아.

  회색 `#5f6b7c`·`#738091`·`#8f99a8`·`#abb3bf`·`#c5cbd3`, 밝은 글자 단계 `#d3d8de`~`#f6f7f9`, 파랑 `#184a90`·`#215db0`·`#2d72d2`·`#4c90f0`·`#8abbff`,
  의미색 초록 `#238551`·주황 `#c87619`·빨강 `#cd4246`. 기본 글자 14px·작은 글자 12px, 단추·입력 높이 30px(작은 것 24px), 모서리 4px, 아이콘 16px, 간격 단위 4px.

## 4. 설계 — 정보 검색 (계획 세션의 권장)

### 4.1 작업 M — 메뉴
- `TABS` 순서: 홈 · 시장 · 기관 · 모의매매 · 정보 검색 · 정보 수집 · 더보기. '한국' 탭은 없애고 `/radar`·`/krx`를 더보기의 화면으로 옮겨. 주소는 그대로 둬.
- 더보기 화면은 묶음 두 개 — '한국 시장'(수급 레이더 · 파생·투기세력)과 지금의 메뉴 묶음. 통합 검색에서 "한국"으로 두 화면이 계속 찾히게 검색어를 남겨.
- 좁은 화면 탭 바: 운영자는 홈 · 시장 · 기관 · 모의매매 · 정보 검색 · 더보기(6칸), 회원은 모의매매가 빠져 5칸. 정보 수집은 지금처럼 더보기 맨 위 행.

### 4.2 대상(객체) 중심 화면
팔란티어에서 가져올 것은 **대상 중심의 쓰는 방식**이야 — 검색해서 대상 하나를 열고, 그 대상의 속성·시간순 자료·연결된 대상을 한 화면에서 보고, 연결을 따라 옆 대상으로 넘어가.

- 대상 종류: 기업 · 기관 · 사람 · 주제(어디에도 없는 검색어).
- 위쪽 검색창 하나. 치는 동안에는 이미 가진 색인으로 후보(종류 아이콘·이름·식별자)만 보이고, 외부 출처는 후보를 고르거나 Enter를 눌렀을 때만 불러.
- 대상 화면의 탭:

| 탭 | 보여 주는 것 | 대상 |
|---|---|---|
| 타임라인 | 아래 탭의 자료를 최신순 한 줄기로(대상을 열면 처음 뜨는 탭) | 전부 |
| 뉴스 | 구글 뉴스(한·영)·Bing 뉴스·새 피드 묶음(§4.8), 종목이면 Yahoo·네이버 종목 뉴스·연합인포맥스, 미국 종목이면 Finviz(단계 5 — 서버에서만) | 전부 |
| 공시 | SEC 공시(회사별 목록 + 이름 전문 검색), DART 공시 | 기업·기관·사람 |
| 리서치 | 국내 종목 리포트(지금 있는 `quote.research` 그대로), 미국 종목의 투자의견 변경 이력 | 기업 |
| 글·논평 | 수집 글(블로그 14곳·waedge) 본문 검색, 거장 견해 | 전부(운영자 — D-1) |
| 보유 | 기업은 13F 보유 기관, 기관은 포트폴리오 상위와 분기 변화(둘 다 지금 있는 API) | 기업·기관 |
| 연결 | 관계 종류별 목록 — 운용자 ↔ 기관, 임원·내부자 ↔ 기업, 소유·창업, 모회사·자회사. 누르면 그 대상으로 넘어감 | 전부 |

- 오른쪽 속성 칸: 아무 줄도 고르지 않았을 때는 대상의 속성(종류·한글/영문 이름·별칭·티커·CIK·설명·바로가기), 줄을 고르면 그 줄의 미리 보기(요약·출처·원문 열기).
- 대상을 고르지 않은 첫 화면: 관심 대상 목록과 새 피드 묶음의 최근 글(운영자에게는 속보도).
- 주소가 상태를 가져(`/search?e=…&tab=news&range=30d` 같은 모양) — 새로고침·뒤로 가기·북마크가 되게.
- 차트와 시세는 넣지 않아. 종목이면 '종목 상세' 바로가기를 둬.

### 4.3 최근 2년 규칙
- 조회 창은 오늘(KST — `Kst.today()`)부터 2년 전까지야. 기간 단추는 7일 · 30일 · 1년 · 2년, 기본은 30일.
- 출처가 기간을 받으면 줘(구글 `after:`, DART `bgn_de`, EDGAR 전문 검색 `startdt`). **그래도 서버에서 작성 시각으로 다시 잘라** — 구글의 날짜 연산자는 범위 밖 기사를 섞어 줘.
- 2년보다 오래된 줄은 응답·저장·화면 어디에도 넣지 않아.
- 고른 기간에 자료가 없으면 "이 기간에는 자료가 없습니다"와 더 넓은 기간 단추. 2년 안에 하나도 없으면 "최근 2년 안의 자료가 없습니다".
  출처가 2년보다 오래된 것만 줬다면 그 줄들은 보이지 않고, 안내에 가장 최근 날짜 하나를 함께 적어(§2).
- 작성 시각을 모르는 줄은 2년 안인지 알 수 없으니 타임라인에 넣지 않고, 출처 상태에 건수만 적어("시각을 알 수 없어 뺀 3건").
  정기로 받는 피드에서 온 글은 처음 받은 시각이 있으니 그 시각으로 넣되 '받은 시각'이라고 표시해.
- 저장본 탭(보유 등)도 같아 — 가장 최근 13F 보고가 2년보다 오래면 같은 안내를 내.

### 4.4 대상 풀기
검색어를 그대로 던지지 않고 대상으로 풀어 — 종류, 한글·영문 이름, 별칭, 티커·종목코드, CIK, DART 고유번호, 연결된 대상.
실측에서 `Duquesne Family Office`의 결과 대부분이 드러켄밀러 기사였어. 별칭을 모르면 놓치는 글이 많아.

1. 이미 가진 것부터: 스코어카드 유니버스·종목 찾기(네이버 자동완성 + Yahoo — `/live/symbols`), 13F 기관 목록(운용자 소개 포함), 거장 101명.
2. 공식 표로 보강: SEC `company_tickers.json`(티커 ↔ CIK), DART 고유번호 표(지금 있는 것).
3. Wikidata로 보강: 한국어·영어 이름과 별칭·설명·관계(`P1830` 소유, `P108` 소속, `P112` 창업자, `P249` 티커, `P5531` CIK)만 — 다른 언어의 이름은 받지 않아. 응답은 하루 이상 캐시.
4. 어디에도 없으면 '주제'로 두고 입력 그대로 구문 검색.

- 후보가 여럿이면(동명이인) 자동으로 고르지 말고 사용자가 고르게 해.
- 출처에 보내는 검색식은 따옴표 구문을 OR로 묶어(한국어 판에는 한글 이름·별칭, 영어 판에는 영문). 세 글자 이하의 별칭·티커는 자유 검색어에 넣지 않아(티커는 종목 뉴스 출처에만).
- Yahoo 검색 뉴스는 `relatedTickers`에 그 종목이 있는 줄만 남겨(이름이 비슷한 다른 회사 기사를 거름).
- 사용자가 별칭을 직접 고치는 기능은 단계 6이야.

  매체로 거르는 규칙은 D-9를 따라. 뺀 건수는 출처 상태에 적어.
- 여러 출처를 합칠 때: 같은 글은 정규화한 주소의 해시로 하나만(`info_text.item_id`와 같은 방식 — 경유 주소뿐이면 지금의 제목 앞 24자 규칙), 출처가 준 건수만 적어.

| 차단을 감지하면 재시도하지 않고 멈춤, 지수 간격 + 흔들림 | akshare `utils/http.py` | 이미 우리 계층에 있음 — 새 출처도 같은 규칙으로 | — |

접목하지 않는 것: **akshare의 출처 전부(중화권 — 뉴스 검색·7x24 속보·기업 프로필·목표가 목록·공시·연구보고서)**, FinceptTerminal 피드의 `scmp`(중화권)와 범위 밖 피드,
키가 필요한 출처(OpenCorporates·Finnhub·FMP·Quiver·OpenSecrets·Congress), JS로 토큰을 계산해 보내는 방식(새 의존성), 키 없는 구글 번역 주소, 손으로 적은 동종 기업 표, akquant(출처 없음).

### 4.6 Finviz — 차단 통과 계층을 화면의 요청이 부르는 길
사용자 결정의 '오인 방지·과부하 금지·사람처럼'은 지금 계층이 이미 하는 것(호스트별 고정 프로필, 브라우저와 같은 TLS, 불규칙 간격, 하루 예산, 물러남)이야.
새로 생기는 것은 **사람의 입력이 수집을 일으킨다**는 점이고, 그래서 아래를 지켜(새 ADR의 결정으로 적어).

- 받는 것: 미국 티커가 있는 대상의 종목 화면 한 쪽(`quote.ashx?t=<티커>`)에서 뉴스 목록의 시각·제목·매체·링크. 뉴스와 블로그가 한 목록이라 종류는 매체 이름으로 나누되,
  나눌 근거가 없으면 '뉴스'로 둬(지어내지 않음). 일반 뉴스 화면(`news.ashx`)의 블로그 목록은 실측해 보고 쓸 만하면 관심 대상 대조용으로만 더해.
- 받지 않는 것: 'Show Previous News' 뒤쪽, 유료(Elite)·로그인 화면, 차트·시세·스크리너·내려받기 경로(`robots.txt`가 막는 경로 포함), Finviz 안쪽 경로로 가는 글의 본문.
- 호스트 `finviz.com`을 정책 표에 더해(계층 1 → 계층 2, 하루 예산 초기값은 실측 뒤 정함). 계층 2를 쓰면 `BROWSER_ALLOWED_HOSTS`에도 더해(시험이 대조).
- 검색 한 번이 Finviz에 보내는 요청은 1건. 같은 티커의 결과는 일정 시간 다시 써(초기값 30분). 관심 대상의 정기 수집도 같은 캐시와 예산을 써.
- 한 번에 한 건씩 줄 세워 보내고 요청 사이 지연은 계층의 값을 그대로 써. 그래서 응답은 비동기야 — 공식·RSS·저장본 결과를 먼저 보이고 Finviz는 받는 대로 채워
  (화면에 출처별 상태: 대기·받는 중·완료·캐시·예산 소진·차단·서버에서만).
- 검색이 쓰는 하루 예산은 정기 수집의 예산과 따로 세어. 사용자 한 명·전체의 검색 빈도에도 상한을 둬. 치는 동안의 후보 찾기는 외부를 부르지 않아.
- 로컬·QA에서는 Finviz가 '서버에서만'으로 보여(개인 IP로 내보내지 않음). 끊기면 지금의 끊김 알림(운영 봇 텔레그램 + 화면 안내 띠)에 같이 걸리게 해.
- 넓히지 않는 것: 프록시·IP 돌려쓰기, 퍼즐 풀이·풀이 서비스, 로그인·유료 장벽 통과, 거부당한 뒤 다른 길로 다시 시도(D-2). 서버 IP로 지나가지 못하면 Finviz를 빼고 보고해.
- 실측이 세션 권한에 막히면 다른 길로 돌리지 말고 그대로 보고해.

### 4.7 구조와 경로
- 수집기: 새 서비스(예: `services/search.py`)와 `/live/search…` 경로. 공식·RSS 출처는 공용 세션(`http.get_session`), Finviz는 `fetch.ladder.fetch`.
  수집기는 프로세스 하나라 즉석 검색의 작업 상태는 메모리에 둘 수 있어.
- 백엔드: `feature/search`(컨트롤러·서비스)가 `feature/detail`처럼 수집기를 부르고, 저장본은 `store`로 읽어(ADR 0001).
  경로 초안 — `GET /api/search/entities?q=`(후보), `GET /api/search/feed?e=|q=&tab=&range=`(결과와 출처별 상태, 받는 중이면 `pending`),
  `GET|POST|DELETE /api/search/watch…`(§5). 새 경로는 `AccessPolicy`·`docs/API.md`·`RouteInventoryTest`·`endpoints.test.ts`에 넣어.
- 화면: `lib`의 순수 함수(검색식 만들기·합치기·2년 자르기·중국어 글 가리기·정렬 — ADR 0004), 훅, `components/screens/search`.
  수집 글의 원문 팝업·번역 단추는 정보 수집 화면의 것을 다시 써.
- 상단 통합 검색 결과 맨 아래에 "'검색어' 정보 검색" 행을 두고, 종목·기관 상세의 뉴스 카드에 정보 검색으로 가는 링크를 둬.

### 4.8 새 피드 묶음
- §3의 후보 표에서 '넣음'인 13개를 **새 묶음**으로 받아. 지금의 사건 뉴스 묶음(`FEEDS`·`KR_FEEDS`)에는 더하지 않아 — 그 둘은 모의 매매 패킷이 읽어.
  새 묶음을 패킷이 읽지 않는다는 것을 시험으로 고정해(지금 패킷 고정본 시험이 그대로 통과해야 함).
- 받는 방식은 지금의 사건 뉴스와 같아(ADR 0040 — 피드마다 다른 간격과 무작위 흔들림, `If-None-Match`·`If-Modified-Since` 조건부 요청, 공용 세션의 거부 래치).
  간격은 피드가 글을 내는 빈도에 맞춰 정하고(보도자료는 길게, 경제지는 그보다 짧게) 수치와 근거를 ADR에 적어. 같은 호스트의 두 피드(CNBC)는 시각이 겹치지 않게 해.
- 저장: 제목·요약(피드가 준 것, 길이 상한)·링크·매체·작성 시각·처음 받은 시각만. 본문은 저장하지 않아(Benzinga처럼 피드에 본문이 실려 와도). 2년 규칙과 같은 글 가리기를 적용해.
  보관 기간은 정해서 ADR에 적어(초기값 90일 — 관심 대상에 걸린 글은 관심 대상 표에서 2년).
- 쓰는 곳: 관심 대상의 대조(외부 호출 0건으로 먼저 찾는 흐름), 정보 검색의 뉴스·타임라인(저장본 검색), 대상을 고르지 않은 첫 화면의 최근 글.
  새 묶음은 `/api/info/*`의 자료가 아니라서 회원에게도 제목·매체·시각·링크가 보여(D-1).
- 등록: 데이터셋 이름은 `collector/app/catalog.py`와 `backend/.../store/Datasets.java` 둘 다(`DatasetsParityTest`), 출처 표 `InfoSources`와 `InfoSourcesParityTest`,
  `docs/DATA_SOURCES.md`의 태스크 수와 출처별 한계. 정보 수집 화면의 출처 목록·출처 상태에도 보이게 해.
- 넣기 전에 매체마다 소유가 중국 자본인지 확인해(§2). 확인하지 못한 것은 넣지 말고 보고해.

## 5. 설계 — 관심 대상

- **등록**: 대상 화면 머리의 단추로 등록·해제. 로그인한 사용자마다 자기 목록을 가져(데모는 등록할 수 없음). 상한은 §2(사용자당 회원 10·운영자 50, 서버 전체 100).
- **표 소유(ADR 0008)**: 등록 목록은 백엔드 소유 표(사용자·대상 키·종류·이름·별칭·식별자·등록 시각·마지막으로 본 시각). 수집기는 이 표를 읽기만 해(`paper_settings` 선례).
  모은 글은 수집기 소유 표(대상 키·글 id·종류·제목·매체·출처·언어·작성 시각·처음 받은 시각·원문 주소·요약 — 본문 없음, 2년 지나면 지움). 두 표의 소유 시험을 함께 고쳐.
- **모으는 방법**: 수집기의 polite 속도군 태스크(운영 서버에서만, `Cadence`의 비주기 일정).
  1. 먼저 이미 받아 둔 흐름(새 피드 묶음·사건 뉴스·속보·수집 글)에서 별칭이 든 글을 찾아 — 외부 호출 0건.
  2. 그다음 대상별 질의(구글 뉴스 한·영, Bing 뉴스, SEC·DART, 미국 티커면 Finviz — 단계 5부터)를 낮은 빈도로 보내. 대상 하나의 다음 실행은 3~8시간 안에서 무작위(§2),
     한 번 깰 때 처리하는 대상 수에 상한, 호스트 하루 예산은 즉석 검색·정기 수집과 따로.
  3. 여러 사용자가 같은 대상을 등록해도 한 번만 모아.
- **대조 규칙**(FinceptTerminal의 키워드 감시 모델을 우리에 맞게): 별칭 중 하나가 제목이나 요약에 들어 있으면 일치. 영문은 단어 경계로, 한글은 포함 일치로 보되
  세 글자 이하의 별칭은 쓰지 않아. 대상:글 키가 유일해서 같은 글은 한 번만 들어가.
- **화면**: 정보 검색 왼쪽 칸에 관심 대상 목록(이름·종류·마지막으로 본 뒤 새 글 수). 관심 대상의 타임라인은 저장본에서 바로 그리고,
  '지금 새로 받기'는 즉석 검색과 같은 길(캐시·예산)로 가. 로컬·QA에서는 등록·조회는 되지만 정기 수집은 서버에서만 돈다고 화면에 적어.
- **알림**: 화면의 새 글 수만(§2). 알림함 연결은 단계 6에서 기존 알림 기능에 종류 하나를 더하는 방식으로(대상마다 켬, 기본 꺼짐, 받은 지 오래된 글은 알리지 않음). 텔레그램은 넣지 않아.
- 관심 대상이 모은 글도 모의 매매의 입력이 아니야. 2년 규칙과 중화권 제외가 똑같이 적용돼.

## 6. 설계 — 겉모습(팔란티어식, 어두운 테마 고정)

- **새 의존성 없이** 만들어. Blueprint 패키지를 넣지 않고, §3에 적은 공개 값을 참고해 **정보 검색 화면 안에서만 쓰는 범위 토큰**을 정의해 — 화면의 최상위 요소에 표지를 두고
  그 안에서 `--bg`·`--surface`·`--surface-2`·`--border`·`--border-strong`·`--text`·`--text-2`·`--text-3`·`--accent`와 상태색·모서리 값을 다시 정해(`frontend/src/app/globals.css` 한 파일).
- **늘 어두워.** 범위 토큰은 어두운 값 한 벌뿐이고 앱의 밝음·어두움 전환을 따르지 않아. 범위 요소에 `color-scheme: dark`를 줘서 기본 입력칸·스크롤 막대도 어둡게 해.
  바탕 `#111418`, 패널 `#1c2127`·`#252a31`, 경계 `#2f343c`~`#404854`, 글자는 밝은 단계, 강조 파랑은 `#4c90f0`·`#8abbff` 쪽(어두운 바탕 위 대비를 재서 고름).
- 범위는 정보 검색의 내용 영역이야. 셸(왼쪽 메뉴·상단바)은 앱 테마 그대로 둬 — 앱이 밝음일 때 밝은 셸 옆에 어두운 내용이 놓여. 구현한 뒤 QA 스택 캡처를 보고에 넣어 사용자가 보게 해.
  화면 밖에 그려지는 것(원문 팝업·대화상자·토스트 — 포털)은 범위 표지가 닿지 않으니 이 화면에서 연 것에는 같은 표지를 붙여.
- 밀도: 넓은 화면에서 글자 14px(보조 12px), 단추·입력 30px, 표 행 28~32px, 모서리 4px, 1px 경계. 글자 하한 12px과 lg 미만 누르는 자리 44px은 그대로 지켜.
- 배치(넓은 화면 세 칸): 왼쪽 칸 = 관심 대상 목록과 필터(종류·출처·언어·기간, 각 건수는 '받은 자료 기준'), 가운데 = 대상 머리(종류 아이콘·이름·식별자와 별칭 태그·등록 단추)와
  탭·조밀한 표(시각 KST · 종류 · 매체 · 제목, 날짜별 묶음), 오른쪽 = 속성·미리 보기 칸, 맨 아래 = 출처 상태 줄. 좁은 화면은 한 칸(왼쪽 칸은 접는 서랍, 오른쪽 칸은 아래 시트).
- 키보드: `/`로 검색창(⌘K는 상단 통합 검색 그대로), 위·아래로 줄 이동, Enter로 원문 새 창.
- 지킬 UI 원칙(`docs/specs/2026-10-31-v2-coinbase-ui.md`): 강조 파랑은 누를 수 있는 것에만(A1), 판정·상태는 색만이 아니라 글과 아이콘으로(A5), 대비 4.5:1·포커스 링 2px·고대비 모드(A8),
  화면은 그리기만(A10). 새 팔레트의 대비는 그 명세가 쓰는 검증 방법으로 확인해. 이모지는 쓰지 않고 `components/ui/icons`를 써.
- 화면에 팔란티어의 이름·로고·제품 이름을 쓰지 않아.
- 연결을 그림(노드와 선)으로 보이는 것과 기간 막대(주별 건수)는 단계 6이야 — 넣을 때 "받은 자료 기준"임을 적어(출처가 주는 건수에 상한이 있어 전체 보도량이 아니야).

| 4 | 공시(SEC·DART·이름 전문 검색), 리서치의 투자의견 변경, 연결의 임원·내부자·모회사 | 단계 3 |
| 5 | Finviz 종목 뉴스·블로그 — 화면의 요청이 차단 통과 계층을 부르는 길(§4.6)과 관심 대상의 Finviz 수집 | 단계 4 |
| 6 | 같은 사건 묶기, 별칭 편집, 알림함 연결, 연결 그림, 기간 막대, AI 요약 — 하나씩 | 단계마다 사용자 승인 |

단계 0~5가 승인 범위야. 단계마다 시험을 먼저 쓰고, `make test`를 통과시키고, 커밋·main 병합·CI·배포·보고는 CLAUDE.md의 전달 방식과 `docs/DEVELOPMENT.md` §7을 따라.
브라우저로 보는 시험은 로컬 스택이 아니라 QA 스택에서 해.

## 8. 지킬 것

CLAUDE.md의 절대 규칙이 모두 그대로 적용돼. 이 작업에서 특히 걸리는 것만 적어.

- 정보 검색·관심 대상·새 피드 묶음의 자료는 **모의 매매의 입력으로 쓰지 않아.** 결정 패킷·프롬프트·고정본은 바이트까지 그대로야. 모의 매매 패킷이 읽는 피드 묶음(`news_headlines`·`kr_news_headlines`)에 피드를 더하지 않아.
- 실제 계좌(토스) 자료와 섞지 않아 — 보유 종목으로 관심 대상을 추천·자동 등록하지 않아.
- Finviz와 관심 대상의 정기 수집은 서버에서만 나가(`POLITE_FETCH_ENABLED`). 로컬·QA compose의 고정값을 건드리지 않아.
- 스크래핑은 Finviz 하나야. 네이버 뉴스 검색 화면·네이버 증권 리서치 목록·한경 컨센서스·중국 자본이 소유한 사이트는 스크래핑하지 않고, 다른 스크래핑 대상을 더하려면 사용자에게 먼저 물어.
- 운영자 전용 저장본(`/api/info/*`의 수집 글·거장 견해·속보)에서 온 결과는 운영자에게만 섞어(D-1). `/api/info/*`의 등급은 바꾸지 않아.
- 없는 값은 `null`과 '—'. 시각·건수를 추정해 채우지 않아. 2년 밖의 자료와 중국어 자료는 어디에도 넣지 않아.
- 실패한 출처를 빈 목록으로 숨기지 않아 — 출처별 상태에 사유를 적어.
- **오픈 소스 규칙**:
  - 기본은 **코드를 가져오지 않고 새로 쓰는 것**이야. 가져오는 것은 출처의 주소·인자·응답 모양과 규칙의 정의(문턱값·시간 창) 같은 사실이고, 구현은 우리 구조(수집기 Python · 백엔드 Java · 화면 TypeScript)로
    처음부터 써. 이 길은 저장소가 공개든 비공개든 그대로 유효해.
  - 원본을 옆에 두고 변수 이름·순서만 바꿔 옮기는 것은 새로 쓴 것이 아니야 — 그렇게 고친 코드에도 원본의 라이선스가 그대로 따라와.
  - MIT인 akshare·akquant의 코드를 옮겨 써야 할 일이 생기면 해도 돼. 그때는 저작권 고지와 라이선스 전문을 저장소에 두고(예: `THIRD_PARTY_NOTICES.md`) 옮긴 파일 머리에 출처를 적어.
  - AGPL-3.0인 FinceptTerminal의 코드는 옮기지 않아(다른 언어로 줄 단위 번역하는 것도 포함). 옮기면 이 저장소 전체를 AGPL-3.0으로 내야 하고, 비공개로 바꾼 뒤에도
    다른 사용자가 네트워크로 쓰면 그 사용자에게 소스를 내줄 의무가 생겨. 사용자가 "저장소 전체를 AGPL-3.0으로 한다"고 따로 정하기 전에는 하지 않아(D-10).
  - 실제 응답 원문을 시험 자료로 넣지 않아(구조만 흉내 낸 합성 표본 — ADR 0026 결정 12). 저장소는 지금 공개야(비공개 전환은 미정).
- 검색어·주소의 경로와 인자를 로그에 남기지 않아(호스트만).
- 새 환경변수가 생기면 `.env.example`에 이름만. 연락처가 든 User-Agent는 코드 기본값으로 두지 않아(D-5).
- 새 의존성이 필요해지면 넣기 전에 이유를 보고해.
- 문서: ADR(결정), `docs/API.md`, `docs/DATA_SOURCES.md`(새 출처·태스크 수·한계), `README.md`(주요 기능·메뉴), `docs/ARCHITECTURE.md`(새 흐름), UI 명세에 범위 토큰 절,
  OSS 채택 문서(`2026-10-26-v2-oss-adoption.md`)에 akshare·akquant와 이번에 접목한 줄.

## 9. 결정 거리 (프롬프트의 답을 따라)

| 번호 | 무엇 | 기본값 |
|---|---|---|
| D-1 | 접근 등급 | 회원(`GET /api/detail/news`와 같음). 데모·`store_only`는 외부를 부르지 않고 등록도 못 함. 운영자 전용 저장본에서 온 결과와 글·논평 탭·속보는 운영자에게만. 새 피드 묶음은 회원에게도 보임 |
| D-2 | 차단 통과의 선 | ADR 0026·0035의 한도 그대로(§4.6의 '넓히지 않는 것') |
| D-3 | 본문 | 임의 기사의 본문은 받지 않음. 수집 글만 지금의 팝업·번역 |
| D-4 | 저장 | 즉석 검색은 메모리 캐시만. 새 피드 묶음은 지금의 사건 뉴스와 같은 저장 방식의 새 데이터셋. 관심 대상은 표 둘(백엔드 소유 등록 표, 수집기 소유 글 표) |
| D-5 | User-Agent의 연락처 | SEC는 지금의 `SEC_USER_AGENT`. Wikidata·GLEIF는 연락처 없는 일반 이름으로 시작하고 거절되면 보고 |
| D-6 | 승인 범위와 순서 | 단계 0~5 승인(단계 1을 먼저 배포). 단계 6은 보고 뒤 사용자의 지시로 |
| D-7 | 배포 | 단계마다 main·CI 뒤 서버 배포(실제 매매가 도는 시간대를 피해 `DEVELOPMENT.md` §7대로) |
| D-8 | 브라우저 계층 | 지금의 계층 2 유지. Finviz가 서버 IP로 지나가지 못하면 빼고 보고 |
| D-9 | 결과에 섞여 온 중화권 매체 | 중국어 글은 늘 뺌(고정). 그 밖에는 매체 사이트가 `.cn` 도메인인 글을 빼고, 설정으로 둔 매체 제외 목록에 사용자가 더할 수 있게 함. 실측에서 보인 중화권 영어 매체는 이름을 보고 |
| D-10 | 오픈 소스 코드 | 가져오지 않고 새로 씀. MIT 코드는 고지와 함께 옮겨도 됨. AGPL 코드는 옮기지 않음(§8) |
| D-11 | 새 피드 묶음의 목록 | §3 후보 표의 '넣음' 13개. 서버에서 막히거나 멈췄거나 소유를 확인하지 못한 피드는 빼고 보고 |

## 10. 하지 않는 것

- 종목 차트·시세 표시, 실시간 스트리밍, 주문 기능.
- 네이버 검색 API, GDELT, 유료 웹 검색 API, X·레딧 등 로그인이 필요한 출처.
- 네이버 뉴스 검색 화면·네이버 증권 리서치 목록·한경 컨센서스·중국 자본이 소유한 사이트의 스크래핑.
- 중국어 자료와 중화권 출처(akshare가 쓰는 출처 전부 포함).
- 임의 호스트의 페이지 열기(정책 표 밖 호스트는 계층이 받지 않음), 유료 기사 본문.
- 2년보다 오래된 자료의 조회·저장.
- 밝은 테마의 정보 검색 화면, 텔레그램 알림.
- 정보 검색·관심 대상·새 피드 묶음의 자료를 모의 매매·AI 결정에 넣는 것.
