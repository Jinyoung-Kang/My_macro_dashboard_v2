1. **끌기 중 접힘은 문턱을 지나는 그 프레임에 바뀝니다**(놓을 때까지 기다리지 않음 — 놓으면 그대로 남음). 그래서 '140px 아래에서 놓으면 접힘'과 '레일을 끌어내면 펼침'이 같은
   규칙입니다. 끌어서 접히면 펼친 폭은 끌기 전 값으로 둡니다(지나며 자른 180이 아니라 — 접기 단추·`[`로 펴면 끌기 전 폭).
2. **전환은 접힘이 바뀌는 때만** — 단추·`[`·명령 팔레트·두 번 누르기·Enter·끌기 중 문턱. 끌기 중 문턱을 넘으면 150ms만 켜 두고 다시 끕니다(그 사이의 움직임은
   따라잡는 전환, 그 뒤는 포인터를 바로 따라감). 화살표 걸음과 처음 그릴 때(저장값을 읽어 폭이 바뀜 — 화면을 열 때 메뉴가 움직이지 않게)는 없습니다. 전환을 켜는
   값(React 상태)과 폭(두 저장소)이 같은 프레임에 들어야 전환이 일어나므로 켜고 끄기는 `flushSync`로 먼저 그립니다 — 셸 명령(창의 사용자 이벤트)·프레임 처리기에서
   바꾼 상태는 저장소 알림과 다른 우선순위로 그려질 수 있었습니다.
3. **손잡이 값**: `aria-valuenow`는 펼친 폭이고 접혔으면 하한 180(창 나누개 패턴의 '접힘 = 가장 왼쪽 자리'), 읽는 글이 '접힘(아이콘 레일), 펼치면 260px'로 가릅니다.

4. **저장 때**: 끄는 동안은 이 창에만 두고 놓을 때(pointerup·pointercancel·lostpointercapture) 한 번 씁니다(초당 수십 번 쓰기와 다른 탭의 storage 이벤트를 피함). 키는 바로 씁니다.
5. **셸 변수**: 아무 폭이나 되므로 클래스(`lg:[--shell-nav-w:220px]`)에서 인라인 style로 옮겼습니다. 변수는 좁은 화면에도 있지만 읽는 쪽이 모두 `lg:` 변형입니다.

6. **끄는 동안**: 문서 뿌리에 `data-nav-resizing`을 붙여 `globals.css`(base 층 `!important`)가 손잡이 밖에서도 커서 col-resize·글 고르기 끔을 둡니다. 레일 툴팁은
   포인터 잡기로 열리지 않고, 키보드 포커스로도 열리지 않게 끄는 동안 막습니다. 끈 누름이 섞인 두 번 누르기는 접기로 받지 않습니다(끌고 바로 한 번 더 누른 경우).
7. **전환 중 넘침**: 펼치는 150ms 동안 내용이 상자보다 넓은 몇 프레임이 있어 메뉴(nav)에 `overflow-x-hidden`, 접기 영역에 `overflow-x-clip`을 더했습니다.

누름 자리(WCAG 2.5.8 — 판단 [추정]): 손잡이는 폭 8px(경계선 안 4·밖 4)라 24px 하한에 못 미칩니다. 간격 예외는 해당하지 않습니다(손잡이 가운데의 24px 원이 경계에서 9px 안쪽의

### 그대로 둔 것·범위 밖 (3)

- `error-state-retry-button-on-danger-tint` — 오류 상자(위험 틴트) 안 '다시 시도' 단추의 바탕·경계가 틴트와 거의 같음(1.02·1.32:1). 단추 글은 읽히고(4.5 이상) 경계는 필수 그래픽이 아님.
  덮개 안 단추(D5)처럼 틴트 안 단추 단계를 따로 두는 것은 P4 이후 화면에서 같은 자리가 늘면 다시 봅니다.
- `search-suggest-zero-no-message` — 입력 후보 0건이면 안내가 없음. 개편과 무관한 동작 결정(정보 검색 P7 정리 때 함께 봄).
- `lg-sort-header-summary-text-height` — 기록된 사용자 질문 1(따로 선 링크·정렬 머리·접기 머리의 넓은 화면 글 높이)에 증거로 더함.

### 사용자 결정 거리 (D1 QA에서 새로 생긴 둘 + 묶음 검토가 남긴 둘)

1. 정보 검색 기간 막대(lg 이상): 막대 하나가 4~18.7px 폭의 누르는 단추라 2.5.8(24px) 미달이고 lg에는 대체 고르기가 없음(개편 전부터). 권장: 넓은 화면에도 '날로/주로 좁히기' 고르기를 함께 두고 막대는 지름길로 — P7 정보 검색 정리 때.
2. 툴팁 회색 견본(계좌 상세 도넛 '기타' `#6e6e7c`)이 덮개 면 위 2.88:1. 권장: 코드 그대로, 명세 §3-5에 '툴팁 견본은 이름 글과 늘 함께 나오는 보조 표지라 덮개 면 3:1을 요구하지 않음' 예외로 적음.
3. /regime '지금 국면' 상자·사분면이 국면 범주색(ok·warn·danger 틴트)만 쓰고 아이콘이 없음 — 국면 범주색에도 '상태색은 늘 아이콘 + 글'을 적용할지(적용하면 국면마다 아이콘). P5a.
4. /status 스냅샷 '상태'·'수집'·태스크 '상세' 칸의 색만 쓰는 상태 표시 — 정상 행에도 아이콘을 둘지(P7에서 결함 번호를 받아 처리).
