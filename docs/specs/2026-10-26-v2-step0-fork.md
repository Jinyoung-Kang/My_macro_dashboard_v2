## A. 저장소 (v1 세션)

1. GitHub에 **private** 저장소 `Jinyoung-Kang/My_macro_dashboard_v2`를 만든다(`gh repo create --private`).
   **2026-10-26 결과: v1 세션의 자동 권한 분류기가 이 명령을 막아 만들지 못했다.** 사용자가 GitHub에서 직접 private으로 만들거나, fork 세션이 사용자 허락 뒤
   `gh repo create Jinyoung-Kang/My_macro_dashboard_v2 --private --source=. --remote=origin --push`로 만든다(이미 있으면 `git push -u origin main`만).
   **2026-10-26 fork 세션 결과: 사용자 지시로 공개 저장소로 만들고(`gh repo create … --public`) `main`(e6dfe0f)을 push했다(V8 개정).**
2. 로컬 v1(`~/Projects/My_macro_dashboard_v1`)을 전체 이력으로 `~/Projects/My_macro_dashboard_v2`에 clone한다. `origin`을 새 저장소로 바꾸고 `main`을 push한다.
   **2026-10-26 결과: clone과 `origin` 설정은 끝났다(a7e964d 이후 커밋). push는 1이 끝난 뒤 fork 세션의 첫 일이다.**
3. `.env`·`.env.qa`는 **복사하지 않는다**(B-3에서 fork 세션이 포트를 고쳐 복사). 비밀값을 화면에 출력하지 않는다.
- 확인: `gh repo view Jinyoung-Kang/My_macro_dashboard_v2 --json visibility`가 ~~PRIVATE~~ PUBLIC(V8 개정), `git -C ~/Projects/My_macro_dashboard_v2 log --oneline -1`이 v1 main과 같은 커밋, `git status -sb`가 `main...origin/main`.

   - `/usr/bin/grep -rn 'acro_dashboard_v1' --exclude-dir=node_modules --exclude-dir=.next --exclude-dir=.git .`로 남은 곳을 하나씩 판단한다.

## C. 데이터 이어받기 (fork 세션, 커밋 없음)

1. v1 폴더에서 `make backup` → 파일 경로를 기록. v2 폴더에서 `make restore F=<그 파일>`(ADR 0003 — 끝 표시 확인·한 트랜잭션 교체).
